## 立项 Prompt 编写方法

基于 `prompts_principles.md`，生成 `project_proposal.md` 的 Prompt 应包含以下结构：

### 1. 背景（Background）

```markdown
## 背景

你是一名 AI 工程化项目分析师，负责根据项目需求文档生成立项文档。

**输入材料**：
- v1→v2 升级需求文档
- v2 产品路线图
- v2 初始化计划
- v1→v2 复用分析报告

**项目背景**：
经济模型系统从 v1 升级到 v2，解决以下痛点：
- 自研公式引擎维护成本高
- 无多人协作能力
- 无正式后端支撑
- 安全合规缺失
```

### 2. 目标（Objective）

```markdown
## 目标

请基于输入材料，生成一份**项目立项文档**，包含：

1. 项目基本信息（名称、性质、周期、目标）
2. 立项背景与必要性分析
3. 项目建设目标（含 KPI 量化指标）
4. 核心建设内容（功能优先级：Must/Should/Could/Won't）
5. 非功能需求（性能、安全、可用性）
6. 技术架构设计
7. 项目实施计划（含里程碑）
8. 资源需求与预算
9. 风险评估与应对
10. 项目效益分析
11. 可行性分析（技术+经济）
```

### 3. 限制（Constraints）

```markdown
## 限制

- 必须基于输入材料中的数据进行提炼，禁止凭空编造数据
- KPI 指标必须可量化、可衡量
- 预算估算必须合理，参考行业标准
- 技术架构必须与 v2 路线图一致
- 功能优先级必须符合 MoSCoW 原则
```

### 4. 禁止事项（Prohibitions）

```markdown
## 禁止

- 不要引入输入材料中没有的功能
- 不要使用模糊的时间估算（如"尽快"、"适当时候"）
- 不要遗漏风险评估章节
- 不要跳过可行性分析
- 不要输出未完成的章节（禁止"待补充"字样）
```

### 5. 输出要求（Output）

```markdown
## 输出要求

输出格式：`my_app/reference/project_proposal.md`

文档结构：
1. 文档元信息（版本、编制单位、日期）
2. 各章节完整内容
3. 决策建议（最后一段）

风格：
- 正式、专业的商务文档
- 量化数据优先
- 逻辑清晰、层次分明

质量标准：
- 立项结论必须有明确决策（批准/不批准）
- 风险必须有应对措施
- 预算必须有详细计算依据
```

## 完整 Prompt 示例

```markdown
# 立项文档生成 Prompt

## 背景

你是一名 AI 工程化项目分析师，负责根据项目需求文档生成立项文档。

**输入材料**：
- docs/requirements/v1_v2_analysis.md（v1→v2 复用分析）
- docs/requirements/v2_init_plan.md（v2 初始化计划）
- docs/requirements/v2_product_roadmap.md（v2 产品路线图）
- docs/requirements/v1_v2_upgrade_requirements.md（升级需求）

**项目背景**：
经济模型系统 v1 → v2 升级项目，核心诉求：
1. 财务公式计算零误差（XIRR/XNPV/NPV/IRR）
2. 多人实时协作能力
3. 内网本地化部署
4. 企业级安全合规

## 目标

生成一份**项目立项文档**，输出到 `my_app/reference/project_proposal.md`

## 文档结构要求

1. **项目基本信息**：名称、性质、建设周期、核心目标、复用资产
2. **立项背景与必要性**：现有痛点、立项必要性
3. **项目建设目标**：
   - 量化 KPI（计算精度、协作效率、导入导出成功率、系统可用性）
   - 核心目标（精准、高效、安全、兼容、稳定）
4. **核心建设内容**：
   - MoSCoW 功能优先级矩阵
   - 非功能需求（性能/安全/可用性/可维护性）
   - 技术架构（前端+后端+数据库）
   - 分阶段实施计划
5. **项目实施计划**：里程碑 + 工期估算
6. **资源需求与预算**：人力成本 + 软硬件成本 = 总预算
7. **风险评估与应对**：高/中/低风险 + 应对措施
8. **项目效益分析**：业务效益 + 技术效益 + 管理效益
9. **可行性分析**：技术可行性 + 经济可行性（ROI 计算）
10. **立项结论**：综合评估 + 决策建议

## 限制

- 基于输入材料提炼，禁止凭空编造
- KPI 必须可量化（如：计算精度与Excel偏差=0）
- 预算参考行业标准（人力单价：PM ¥30k/月，开发 ¥25k/月）
- 技术选型与 v2 路线图一致（Vue3 + NestJS + PostgreSQL）

## 禁止

- 禁止"待补充"、"待确认"
- 禁止模糊时间估算
- 禁止缺失任何章节
- 禁止超出 v2 路线图范围的功能

## 输出格式

```markdown
# [项目名称] 项目立项书（审批版）

**文档版本**：V1.0
**编制单位**：技术部
**编制日期**：YYYY-MM-DD

## 一、项目基本信息
...

## 二、立项背景与必要性
...

[完整输出所有章节]
```
```

## 关键要点总结

| 要素 | prompts_principles.md 原则 | 立项 Prompt 应用 |
|------|---------------------------|-----------------|
| **背景** | 项目类型/业务领域 | 输入材料 + 项目背景描述 |
| **目标** | 完成项目初始化 | 生成立项文档 11 个章节 |
| **限制** | 符合行业规范/低耦合 | 基于材料提炼/KPI量化 |
| **禁止** | 不要过度设计/不引入冗余 | 禁止"待补充"/模糊估算 |
| **输出** | 目录结构/配置文件 | 完整立项文档 + 决策建议 |

这样，通过 prompts_principles.md 的 Prompt 框架，你就可以系统性地从输入材料生成高质量的立项文档了。
