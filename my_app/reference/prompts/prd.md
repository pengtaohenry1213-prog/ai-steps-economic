## Prompt

请基于以下项目工程规范文档，生成一份完整的【项目架构文档】，严格遵循所有要求：

### 输入参考文档（必须严格遵守其规则）

1. tracking.md：执行状态追踪表、状态定义、阶段映射、Human Gate记录规范
2. start.md：项目启动指南、环境要求、本地开发流程、Docker部署流程、项目结构
3. execute-plan.md：Agent执行规则、日志格式、Git提交规范
4. generate-plan.md：Plan文件生成规则、输出路径要求
5. human-gate.md：Human Gate核心定义与执行标准
6. run-step.md：全流程执行规范、Human Gate触发条件、实测测试要求
7. step-template.md：单Step模板格式（7个必填字段）
8. steps-dev.md：通用开发阶段划分、依赖逻辑、角色分类

### 文档核心要求

1. **架构部分**：先定义项目整体技术架构和工程化架构，分层明确职责
2. **Step拆分部分**（核心）：将项目全生命周期拆分为可独立执行的Step，每个Step严格遵循step-template.md的7字段格式
3. **执行规范部分**：补充项目统一的执行规则、Human Gate规则、进度追踪规则、版本控制规则
4. **验收闭环部分**：明确所有Step完成后的最终验收标准

### Step拆分强制要求

1. **阶段划分**：必须分为4个标准阶段，严格遵循steps-dev.md的依赖逻辑：
   - 第零阶段：项目初始化（对应start.md的项目启动流程）
   - 第一阶段：基础搭建（前后端基础项目初始化，可并行）
   - 第二阶段：核心功能（后端API优先，再开发对应前端）
   - 第三阶段：集成优化（联调、部署、稳定性优化）
2. **每个Step必须包含**：
   - Step编号：StageX-StepXX格式
   - Step目标：仅聚焦当前Step的具体任务
   - 输入条件：明确前置依赖
   - 执行动作：按顺序列出可执行的操作，必须包含：
     - 代码编写/配置修改动作
     - 调试/验证命令
     - Human Gate执行时机（HG1/HG2）
     - Git提交命令
   - 输出物&验收标准：必须量化可验证，必须包含**实测命令和预期输出**
   - 关联依赖：明确前置和后续Step
   - 文件变更清单：表格形式，列出所有将修改/新增的文件
3. **必须严格遵循run-step.md的执行流程**：
   - 开发阶段Step执行前执行Human Gate 1
   - 测试/验收阶段Step执行后执行Human Gate 2
   - 每个Step必须包含实测测试要求，不允许只写"通过"
   - 每个Step完成后必须有明确的Git提交命令
4. **必须严格遵循tracking.md的规范**：
   - 明确每个Step的状态更新规则
   - 明确更新日志的记录要求
   - 明确阻塞问题的追踪方式

### 文档结构（严格按此顺序）

1. 文档概述：说明文档目的和适用范围
2. 核心架构体系：
   - 项目技术架构（分层表格，包含层级、核心组件、技术栈、职责）
   - 工程化架构（表格形式，包含模块、核心配置、工具、目标）
3. 项目全生命周期拆分步骤：
   - 第零阶段：项目初始化（对应start.md）
   - 第一阶段：基础搭建（后端基础→前端基础）
   - 第二阶段：核心功能（后端核心API→前端核心组件→集成验证）
   - 第三阶段：集成优化（部署优化→稳定性优化）
   （每个阶段下的每个Step严格使用step-template.md的表格格式）
4. 执行规范补充：
   - Plan文件生成规则（对应generate-plan.md）
   - Human Gate执行规则（对应human-gate.md和run-step.md）
   - 进度追踪规则（对应tracking.md）
   - 版本控制规则（对应execute-plan.md）
5. 验收闭环：明确所有Step完成后的最终验收标准

### 项目专属参数（可根据实际项目替换）

- 项目类型：前后端一体化Monorepo项目
- 包管理工具：pnpm workspace
- 前端技术栈：Vue3 + TypeScript + Vite
- 后端技术栈：Node.js + Express + TypeScript
- 数据层：MySQL + Redis
- 部署方式：Docker + Docker Compose
- 核心功能模块：用户模块（示例，可替换为实际项目核心模块）

### 强制约束

1. 所有规则必须严格对齐输入的8份工程规范文档，不得自行修改
2. 每个Step必须可独立执行，粒度清晰，一个Step对应一个独立功能块
3. 所有验收标准必须可量化、可验证，必须包含实际可执行的命令
4. 必须明确每个Step的Human Gate执行时机和决策标准
5. 必须明确每个Step完成后的Git提交命令和更新tracking.md的要求
6. 不允许生成空泛的描述，所有内容必须可直接用于项目执行
