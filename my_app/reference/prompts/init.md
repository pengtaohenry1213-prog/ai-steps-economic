# 任务

# 固定文档结构（必须严格按以下顺序生成）

1. 文档头部：文档版本、编制单位、编制日期
2. 一、项目基本信息：表格（项目名称、项目性质、建设周期、核心目标、复用资产）
3. 二、立项背景与必要性：现有系统痛点（4大核心问题）、立项必要性（4点）
4. 三、项目建设目标：量化KPI表格（指标、目标值、衡量方式）、核心目标（5点）
5. 四、核心建设内容：MoSCoW功能优先级表格、非功能需求表格、技术架构（代码块）、技术选型、外部依赖、核心必建功能（第一阶段）、扩展功能（第二阶段）
6. 五、项目实施计划：阶段周期交付成果表格、核心里程碑
7. 六、资源需求与预算：人力成本表格、软硬件运营成本表格、总预算表格
8. 七、风险评估与应对措施：风险类型/等级/应对措施表格
9. 八、项目效益分析：业务效益、技术效益、管理效益
10. 九、技术与经济可行性分析：技术可行性表格、经济可行性表格、立项结论表格、综合建议、决策建议

# 内容规范

1. 量化指标必须明确（计算精度、效率提升、兼容率、可用性、NPS）
2. 技术架构用代码块绘制层级结构，技术栈为企业主流前后端方案
3. 预算数据为企业级合理数值，包含人力、硬件、运营成本
4. 风险分级：高/中/低，对应明确应对措施
5. 可行性分析必须包含技术、经济、风险三维度，输出明确立项结论
6. 全程使用正式商务用语，符合立项审批文档要求

# 输出要求

1. 纯Markdown格式，文件名：init.md
2. 无注释、无多余说明、无空行冗余
3. 表格对齐规范，代码块格式正确
4. 替换【XX】为具体项目名称，保持文档完整可直接用于审批
