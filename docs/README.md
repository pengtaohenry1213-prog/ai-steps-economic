## 项目核心特征

- 有 10 份完整 Spec 文档（架构、协作、公式、RAG、Agent、安全、合规）
- 技术栈复杂：Vue3/React + vxe-table + Yjs + Supabase + HyperFormula + RAG + ReAct/CoT Agent
- 开发范式严格：Vibe 验证 → Spec 固化 → Human Gate 把关 → 代码实现
- 要求极高：零错误、零泄漏、无冲突、合规、可审计
- 模块极多：前端渲染、协作同步、后端服务、AI 智能体、安全脱敏

## 核心原因

| 理由 | 说明 |
| --- | --- |
| **Spec 是"开发合同"** | 没有 Spec，AI 生成的代码没有约束，容易偏离需求 |
| **Spec 决定代码结构** | 8+1 份 Spec 定义了模块边界，代码骨架必须按 Spec 拆分 |
| **Human Gate 依赖 Spec** | Gate 2 评审的是 Spec，没有 Spec 无法进入开发阶段 |
| **避免返工** | 先写 Spec 再写代码，比先写代码再改架构成本低 10 倍 |

## Spec 文档模板格式（统一规范）

每份 Spec 必须包含以下章节：

```markdown
# Spec-XX: [名称]

## 1. 目标与范围
- 本 Spec 解决什么问题
- 不解决什么问题（明确边界）

## 2. 术语定义
- 关键术语表

## 3. 设计原则
- 必须遵守的约束（如：100%准确、零泄漏）

## 4. 详细设计
- 架构图
- 接口定义
- 数据模型
- 状态机/流程图

## 5. 接口契约
- 输入/输出格式
- 错误码定义

## 6. 测试策略
- 单元测试覆盖点
- 集成测试场景

## 7. 验收标准
- 必须通过的 checklist
- 性能指标

## 8. 关联 Spec
- 依赖的其他 Spec 编号
- 被依赖的 Spec 编号

## 附录
- 参考文档
- 决策记录（ADR）
```
