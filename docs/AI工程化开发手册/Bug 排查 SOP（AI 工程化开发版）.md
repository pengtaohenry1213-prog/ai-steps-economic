# Bug 排查 SOP（AI 工程化开发版）

---

# 一、Bug 排查真正核心

很多人排查 Bug 的方式：

```txt
这里改一下
那里试一下
再问AI
再乱改
```

结果：

- Bug 越修越多
    
- 项目越来越乱
    
- AI 开始疯狂重构
    

真正正确方式：

# 用“证据链”排查 Bug

---

# 二、Bug 排查黄金原则（极重要）

# 没有证据

≠  
没有问题

---

# 另一个核心原则

# 两次无新增证据

必须停止 AI 修改

否则：

AI 会开始：

- 猜测
    
- 乱改
    
- 扩散问题
    

这是 AI 工程化最大风险之一。

---

# 三、Bug 排查标准流程（SOP）

---

# Step1：确认 Bug 是否真实存在

先确认：

- 是否稳定复现
    
- 是否偶发
    
- 是否环境问题
    
- 是否缓存问题
    

---

---

## 1. 刷新页面

```txt
Ctrl + F5
```

---

## 2. 清缓存

---

## 3. 重启服务

```bash
npm run dev
```

---

## 4. 看控制台

浏览器：

```txt
F12
Console
```

---

# 四、Step2：明确“现象”

不要只说：

❌ “坏了”

必须明确：

---

# Bug 描述模板

```txt
问题：

现象：

复现步骤：

预期结果：

实际结果：

最近修改：

是否稳定复现：
```

---

# 示例

```txt
问题：
点击登录按钮后无反应

现象：
页面没有跳转

控制台报错：
Cannot read property xxx of undefined

复现步骤：
1. 输入账号密码
2. 点击登录
3. 页面无变化

预期：
进入首页

实际：
无反应

最近修改：
新增权限模块
```

---

# 五、Step3：先定位“问题层级”（核心）

不要一上来乱改代码。

先确认：

---

# Bug 属于哪一层？

|层级|常见问题|
|---|---|
|UI层|样式错乱、点击失效|
|状态层|数据没更新|
|API层|请求失败|
|权限层|Token失效|
|路由层|页面不跳转|
|服务端|接口异常|
|数据层|数据为空|
|环境层|配置错误|

---

# 六、Step4：最小复现（极重要）

# Bug 越小

越容易修

---

# 正确方式

---

## 1. 去掉无关代码

例如：

- 去掉复杂组件
    
- 去掉动画
    
- 去掉权限
    

---

## 2. 缩小输入范围

例如：

```txt
只有空数据才报错？
只有某个用户才报错？
只有移动端报错？
```

---

## 3. 独立测试

单独测试：

- API
    
- 函数
    
- 组件
    

---

# 十二、AI Debug 正确工作流（真正重要）

# 错误方式

```txt
报错了帮我修
```

AI 会：

- 猜
    
- 乱改
    
- 顺手重构
    

---

# 正确方式

```txt
问题：

现象：

1. 分析根因
2. 给出排查步骤
3. 给出修复方案

先不要直接改代码。
```

# 十五、最常见 Bug 分类（非常实用）

---

# 1. undefined/null

最常见。

解决：

```javascript
if (!data) return
```

---

# 2. 异步问题

表现：

- 数据未返回就使用
    

解决：

```javascript
await
```

---

# 3. 响应式丢失（Vue）

表现：

- 数据更新页面不刷新
    

---

# 4. this 指向问题

表现：

- 方法失效
    

---

# 5. 类型错误（TS）

表现：

```txt
xxx is not assignable
```

---

# 6. API 数据结构变化

最容易被忽略。
