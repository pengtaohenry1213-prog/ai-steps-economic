# Cursor 使用规范（AI 工程化开发版）

---

# 一、Cursor 的定位

Cursor 本质上不是：

> “AI聊天工具”

而是：

# AI 编程工作台

核心作用：

- 理解整个项目上下文
    
- 帮你修改代码
    
- 帮你生成模块
    
- 帮你排查 Bug
    
- 帮你维护工程结构
    

所以：

> Cursor 要像“工程协作伙伴”使用，  
> 而不是“随便聊天”。

---

# 二、Cursor 最核心原则

# 小任务 + 小修改 + 小验证

不要：

❌ 一次让 Cursor 重构整个项目

正确方式：

✅ 一次只处理：

- 一个组件
    
- 一个页面
    
- 一个功能
    
- 一个 Bug
    

---

# 三、Cursor 标准工作流（推荐）

---

# Step1：先让 Cursor 理解项目

不要一上来直接：

> “帮我改 Bug”

正确方式：

先让 Cursor 读项目。

例如：

```txt
请先阅读当前项目结构，
分析：
1. 技术栈
2. 目录结构
3. 状态管理方案
4. 路由结构
5. API组织方式
6. UI组件体系

不要修改代码，
只做分析总结。
```

---

# Step2：让 Cursor 输出理解结果

要求 Cursor 输出：

- 项目结构
    
- 风险点
    
- 不规范代码
    
- 可优化点
    

目的：

> 先确认 AI 是否真正理解项目。

---

# Step3：明确修改边界

永远不要说：

❌ “帮我优化一下”

必须说清：

```txt
只修改：
src/views/login

不要修改：
- 全局样式
- 路由
- API层
- 其他页面

不要重构项目。
```

---

# Step4：先出方案，再写代码

复杂需求：

不要直接生成代码。

先让 Cursor：

- 出方案
    
- 出文件清单
    
- 出影响范围
    

例如：

```txt
先不要写代码。

请先输出：
1. 修改方案
2. 涉及文件
3. 数据流变化
4. 风险点
5. 回滚方案
```

---

# Step5：小步提交

每完成一个小功能：

- 测试
    
- Git提交
    
- 再继续下一步
    

不要连续改几十个文件。

---

# 四、Cursor Prompt 规范（核心）

---

# 1. 必须写“限制条件”

例如：

```txt
要求：
- 使用 TypeScript
- 不新增依赖
- 不修改现有接口
- 保持现有代码风格
- 保持移动端兼容
```

---

# 2. 必须写“禁止事项”

例如：

```txt
禁止：
- 不要重构无关代码
- 不要修改UI风格
- 不要修改文件命名
- 不要删除现有注释
```

---

# 3. 必须要求“解释原因”

例如：

```txt
修改后请说明：
1. 为什么这样改
2. 修复了什么问题
3. 是否有副作用
```

---

# 五、Cursor 上下文管理规范

---

# 1. 不要长时间连续对话

Cursor 上下文会逐渐漂移。

表现：

- 开始乱改
    
- 忘记之前规则
    
- 修改越来越危险
    

建议：

- 一个功能一个会话
    
- 一个 Bug 一个会话
    

---

# 2. 大项目必须写 PROJECT_STATE.md

建议维护：

```txt
当前项目阶段：
当前正在开发：
已完成：
当前Bug：
禁止修改模块：
下一步计划：
```

然后：

> 每次先让 Cursor 阅读 PROJECT_STATE.md

---

# 3. 建 references 目录

用于存：

- 标准按钮
    
- 标准表单
    
- 标准表格
    
- 标准弹窗
    
- 标准请求封装
    

目的：

> 不让 Cursor 每次自由发挥。

---

# 六、Cursor 开发纪律

---

# 1. 禁止 AI 一次生成几千行代码

超过：

- 300~500 行
    

风险就明显升高。

因为：

- Bug难查
    
- AI容易失控
    
- 后期难维护
    

---

# 2. 一个文件只做一类事情

例如：

❌ Login.vue 里面：

- UI
    
- API
    
- 工具函数
    
- 权限逻辑
    
- 数据转换
    

全混一起。

---

正确：

```txt
views/
components/
services/
hooks/
utils/
types/
```

---

# 3. 复杂逻辑必须模块化

例如：

不要：

```txt
if else if else if else...
```

应该：

- 拆函数
    
- 拆模块
    
- 拆策略
    

因为：

> AI 最怕巨型函数。

---

# 七、Cursor Debug 规范（非常重要）

---

# 1. 不要只发一句“报错了”

错误示范：

```txt
这个报错了，帮我修
```

---

正确：

```txt
问题：
点击登录按钮无反应

现象：
控制台报错：
xxx

复现步骤：
1.
2.
3.

我怀疑：
可能是请求未触发
```

---

# 2. 两次无新增证据，必须停止

如果 Cursor：

- 连续两次没修好
    
- 没新增信息
    
- 开始乱改
    

必须停止。

正确做法：

---

## 最小复现

缩小问题。

---

## 打日志

打印：

- 参数
    
- 返回值
    
- 分支
    

---

## 看网络请求

检查：

- Request
    
- Response
    
- 状态码
    

---

## Git回滚

回到稳定版本。

---

# 八、Cursor + Git 标准流程（强烈推荐）

---

# 开发流程

```txt
新功能
→ 新分支
→ Cursor开发
→ 本地测试
→ Git提交
→ 合并主分支
```

---

# Commit 规范

例如：

```txt
feat: 新增登录页面
fix: 修复表单校验
refactor: 拆分用户模块
style: 调整按钮样式
```

---

# 九、Cursor 安全规范

---

# 1. 密钥禁止进前端

不要：

```txt
const API_KEY = "xxx"
```

必须：

```txt
.env
```

---

# 2. 不信任前端

服务端必须：

- 鉴权
    
- 权限校验
    
- 参数校验
    

---

# 3. AI 生成代码必须人工检查

重点检查：

- SQL
    
- 权限
    
- 登录
    
- 文件上传
    
- 支付
    

---

# 十、Cursor 最佳适用场景

---

# 最适合

✅ 管理后台  
✅ CRUD系统  
✅ 工具网站  
✅ MVP项目  
✅ 数据展示页  
✅ 前端重构  
✅ UI组件开发

---

# 不适合

❌ 超大型微服务  
❌ 金融核心系统  
❌ 高安全系统  
❌ 超复杂算法系统

---

# 十一、Cursor 高级玩法（真正拉开差距）

---

# 1. AI 不只是写代码

更重要的是：

- 读代码
    
- 理解代码
    
- 解释代码
    
- 重构代码
    
- 补测试
    
- 写文档
    

---

# 2. 把 Cursor 当“团队成员”

你需要：

- 给规范
    
- 给边界
    
- 给上下文
    
- 给参考实现
    

而不是：

> “你自己看着办”

---

# 3. 真正高手的核心

不是：

> 会不会写代码。

而是：

# 会不会控制 AI 的输出质量。

---

# 十二、Cursor 万能控制 Prompt（推荐保存）

```txt
重要要求：

1. 先分析，不要直接改代码
2. 只修改我指定范围
3. 不要重构无关代码
4. 不要改变UI风格
5. 保持现有技术栈
6. 保持现有代码风格
7. 优先最小修改方案
8. 修改后解释原因
9. 输出影响文件列表
10. 如有风险先提示
```

---

# 十三、最终核心思想

Cursor 最大价值不是：

> “自动写代码”

而是：

# 提升工程效率

真正危险的不是：

> AI 不会写代码

而是：

> AI 在你不知情时，  
> 悄悄改坏整个项目。
