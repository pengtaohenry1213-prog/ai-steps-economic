# 迭代阶段操作指南

## 概述

迭代阶段（Iteration）用于在项目开发过程中追加新的需求和任务。当现有功能需要扩展或发现新需求时，通过迭代阶段生成新的 Step 文档，交给 Cursor 执行。

**核心原则**：迭代阶段不会重新初始化项目，只在现有项目基础上追加新的 step 文档。

## 迭代流程

```
workflow-dashboard                      Cursor
      │                                    │
      │  1. 进入 iteration 阶段             │
      │  2. 添加新需求                      │
      │  3. AI 分析需求                     │
      │  4. 生成新的 stepN.md             │
      │  5. 保存到项目目录                  │
      ↓                                    │
      │  ◄────── Cursor 执行 ──────────────│
      │                                    │
      │                           执行 stepN.md
      │                           检查下一个 step
      │                           循环执行直到完成
```

## 与其他阶段的关系

| 阶段 | 说明 |
|------|------|
| init ~ initialization | 在 workflow-dashboard 管理，产出项目脚手架 |
| development ~ acceptance | Cursor 执行预生成的 step1, step2, ... |
| iteration | 追加新的 stepN.md，Cursor 继续执行 |

## 操作步骤

### 步骤 1：进入迭代阶段

在 workflow-dashboard 中，将生命周期进度推进到 **iteration** 阶段。

### 步骤 2：添加新需求

点击"添加新需求"按钮，输入或上传新需求内容：

- 功能描述（新功能是什么）
- 优先级（P0/P1/P2）
- 验收标准（如何判断完成）

### 步骤 3：AI 分析需求

AI 分析新需求内容，判断：

- 是否需要在现有代码基础上修改
- 是否需要新增文件
- 与现有 step 的依赖关系
- 优先级和执行顺序

### 步骤 4：生成 Step 文档

系统生成 `step{N}.md` 文档，内容结构：

```markdown
# Step {N}: {功能名称}

## 任务目标
{新功能的具体描述}

## 约束条件
- 遵循前端工程化 SOP
- 遵循后端工程化 SOP
- 遵循数据库设计规范
- 遵循安全工程规范

## 验收标准
- [ ] 功能可正常运行
- [ ] 单元测试覆盖率 > 70%
- [ ] 无安全漏洞

## 涉及文件
- src/views/{Component}.vue
- src/api/{api}.ts

## 前置依赖
- step{N-1}.md (如有)
```

### 步骤 5：保存到项目目录

Step 文档保存到：

```
v2/dev/{projectName}/docs/steps/step{N}.md
```

## Cursor 执行机制

Cursor 完成当前 step 后，自动检查下一个 step：

```
docs/steps/
├── step1.md  ✅ 已完成
├── step2.md  ✅ 已完成
├── step3.md  ✅ 已完成
└── step4.md  🔄 待执行（新追加）
```

**Cursor 行为**：

1. 读取 `docs/steps/step4.md`
2. 按 run-step.md 流程执行
3. 完成 → 检查 step5 是否存在
4. 循环执行直到所有 step 完成

## 追加 vs 重新初始化

| 场景 | 操作 | 说明 |
|------|------|------|
| 新增功能 | 追加 step | 在现有项目基础上增量开发 |
| 现有功能修改 | 追加 step | 覆盖或修改已有功能 |
| 技术重构 | 追加 step | 标记为技术债务修复 |
| Bug 修复 | 追加 step | 标记为 fix 类型 |
| 项目重启 | 重新初始化 | 不推荐，会丢失现有代码和历史 |

**为什么不要重新初始化？**

- 现有代码已通过测试/验收
- 保留 git 历史和版本记录
- 只需在现有基础上增量开发
- 保持项目稳定性

## 迭代阶段与 Human Gate

迭代阶段默认情况下 **不需要 Human Gate**：

| 阶段 | HG1 | HG2 |
|------|-----|-----|
| init ~ initialization | ❌ | ❌ |
| development | ✅ | ❌ |
| testing | ✅ | ✅ |
| acceptance | ✅ | ✅ |
| packaging ~ iteration | ❌ | ❌ |

如果项目规模较大或涉及安全敏感功能，可以在迭代阶段增加 Human Gate 审批。

## 注意事项

1. **不要重新初始化**
   - 迭代阶段不会重新生成项目脚手架
   - 不会复制 Cursor Rules（已存在）
   - 只追加 step 文档

2. **保持一致性**
   - 新 step 必须遵循项目已有的 Cursor Rules
   - 使用相同的代码规范和目录结构

3. **前置依赖**
   - 确保新 step 的依赖关系正确
   - 如有依赖，在 step 文档中明确标注

4. **版本管理**
   - 每次迭代完成后，建议 git commit
   - 提交信息：`feat(iteration): 完成 step{N} - {功能描述}`

5. **测试覆盖**
   - 新功能必须包含测试用例
   - 修改现有功能需更新相关测试

## 示例

### 示例 1：添加用户管理模块

**输入**：

```
新需求：添加用户管理模块，包括用户列表、编辑、删除功能
优先级：P1
验收标准：CRUD 操作正常运行，界面符合设计规范
```

**AI 生成**：

```markdown
# Step 4: 用户管理模块

## 任务目标
实现用户管理模块，包含：
- 用户列表页面（分页、搜索）
- 用户编辑弹窗
- 用户删除确认

## 约束条件
- 遵循前端工程化 SOP
- 遵循安全工程规范（无越权访问）
- 使用项目已有的 UI 组件库

## 验收标准
- [ ] 用户列表正常显示和分页
- [ ] 用户编辑保存成功
- [ ] 用户删除前有确认提示
- [ ] 无 SQL 注入和 XSS 漏洞

## 涉及文件
- src/views/UserList.vue
- src/views/UserEdit.vue
- src/api/users.ts
- src/stores/user.ts

## 前置依赖
- step1.md (已完成)
- step2.md (已完成)
- step3.md (已完成)
```

**Cursor 执行**：

1. 读取 `docs/steps/step4.md`
2. 生成 Plan
3. 执行开发
4. 实测测试
5. 验收通过
6. git commit

## 常见问题

**Q：迭代阶段可以追加多个 step 吗？**
A：可以。每次添加新需求都会生成一个新的 step 文档。

**Q：可以跳过当前的 step 直接执行下一个吗？**
A：不建议。step 之间可能有依赖关系，跳过可能导致代码不完整。

**Q：迭代阶段生成的 step 文档在哪里查看？**
A：在项目目录 `v2/dev/{projectName}/docs/steps/` 下查看。

**Q：迭代阶段完成后需要手动通知 Cursor 吗？**
A：不需要。Cursor 完成当前 step 后会自动检查下一个 step。

**Q：如果迭代过程中发现问题怎么办？**
A：可以在当前 step 中创建新的 fix 类型 todo，或追加一个新的 step 来处理。
