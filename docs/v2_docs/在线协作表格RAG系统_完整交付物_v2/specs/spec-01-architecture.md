## 1. 目标与范围

### 1.1 目标
定义在线表格多人协作 + RAG 智能助手系统的整体技术架构，明确各组件职责、交互协议与部署拓扑。

### 1.2 范围
- ✅ 前端渲染层（Vue3/React + vxe-table）
- ✅ 协作同步层（Yjs CRDT + y-websocket）
- ✅ 基础设施层（Supabase 本地化）
- ✅ 公式计算层（HyperFormula）
- ✅ RAG 智能助手层（Embedding + Rerank + LLM）
- ✅ 安全与合规层（脱敏 + 审计 + 等保）

### 1.3 不在范围内
- ❌ 移动端原生 App 开发
- ❌ 第三方 SaaS 集成（如钉钉/企微）
- ❌ 离线全量数据导出（仅支持脱敏后导出）

## 2. 术语定义

| 术语 | 定义 |
|------|------|
| CRDT | Conflict-free Replicated Data Type，无冲突复制数据类型 |
| Y.Doc | Yjs 的核心文档对象，承载所有协作数据 |
| Awareness | Yjs 的在线状态同步机制（光标、选区、用户信息） |
| HyperFormula | 开源公式计算引擎，兼容 Excel 386+ 函数 |
| RAG | Retrieval-Augmented Generation，检索增强生成 |
| HyDE | Hypothetical Document Embeddings，查询改写技术 |

## 3. 设计原则

| 原则 | 说明 | 优先级 |
|------|------|--------|
| **公式零误差** | 财务公式计算结果必须 100% 准确，不可容忍浮点误差 | P0 |
| **数据零泄漏** | 敏感字段（税号、金额、手机号）全程脱敏，传输/存储/展示均不可泄露明文 | P0 |
| **协作无冲突** | 多人同时编辑同一单元格，Yjs CRDT 自动合并，禁止覆盖 | P0 |
| **内网可运行** | 所有组件支持本地化 Docker 部署，无外网依赖 | P0 |
| **审计可追溯** | 每一次编辑、查询、导出操作均记录完整审计日志 | P0 |

### 4.2 组件职责矩阵

| 组件 | 职责 | 技术选型 | 部署方式 |
|------|------|---------|---------|
| 前端渲染 | 表格 UI、交互、虚拟滚动 | Vue3/React + vxe-table@4.9.31 | CDN/静态服务器 |
| 协作同步 | 多人实时编辑、冲突解决 | Yjs + y-websocket | 与前端同域 |
| 数据持久化 | 表格数据存储、用户认证、权限 | Supabase (PostgreSQL + Auth) | Docker Compose |
| 公式计算 | 公式解析、依赖追踪、重计算 | HyperFormula | 前端 Worker / 服务端 |
| RAG 检索 | 意图识别、向量检索、重排序 | BGE-M3 + Qdrant + bge-reranker | GPU 服务器 |
| LLM 生成 | 自然语言回答、Function Calling | Qwen2.5-72B-INT4 | GPU 服务器 |

### 4.3 数据流图

#### 4.3.1 正常编辑流

```
用户 A 编辑单元格 (0,0)
    │
    ▼
vxe-table 触发 cell-change 事件
    │
    ▼
Y.Doc 更新 (CRDT 操作)
    │
    ├──► y-websocket 广播给 用户 B/C
    │
    ▼
Supabase Realtime 持久化 (异步)
    │
    ▼
PostgreSQL 写入操作日志 (audit_log 表)
```

#### 4.3.2 RAG 查询流

```
用户输入: "Q3 华东区销售额总和"
    │
    ▼
意图识别 (意图: AGGREGATE_QUERY)
    │
    ▼
表格 Schema 检索 (Qdrant: 找到"销售额""华东区"相关 Chunk)
    │
    ▼
结构化查询生成 (SQL / HyperFormula 公式)
    │
    ▼
数据查询 (PostgreSQL / 前端 HyperFormula)
    │
    ▼
数据脱敏 (金额保留格式，税号/姓名脱敏)
    │
    ▼
LLM 生成自然语言回答 (Qwen2.5-72B)
    │
    ▼
结果返回 (回答 + 高亮单元格 + 推荐公式)
    │
    ▼
审计日志记录 (query_log 表)
```

### 4.4 状态管理设计

```typescript
// 全局状态 (Zustand / Pinia)
interface AppState {
  // 表格状态
  table: {
    sheetId: string;
    data: any[][];           // vxe-table 渲染数据
    formulas: FormulaMap;    // 单元格 → 公式映射

  // 协作状态
  collaboration: {
    yDoc: Y.Doc;
    provider: WebsocketProvider;
    awareness: Awareness;
    onlineUsers: User[];

  // RAG 状态
  rag: {
    isOpen: boolean;
    messages: ChatMessage[];
    lastQuery: string;
    lastResult: RagResult;
  };

  // 用户状态
  user: {
    id: string;
    role: 'admin' | 'editor' | 'viewer';
    permissions: Permission[];
  };
}
```

## 5. 接口契约

### 5.1 前后端通用接口规范

- **协议**: HTTP/2 + WebSocket
- **格式**: JSON
- **认证**: JWT (Bearer Token)，有效期 2 小时
- **分页**: cursor-based，默认 pageSize = 50
- **错误码**: 统一格式

```json
{
  "code": "ERR_001",
  "message": "单元格被锁定",
  "detail": { "cell": "A1", "lockedBy": "user_123" },
  "requestId": "req_abc123"
}
```

### 5.2 核心 API 列表

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 获取表格数据 | GET | `/api/sheets/{id}` | 含权限校验 |
| 保存表格快照 | POST | `/api/sheets/{id}/snapshot` | 手动保存版本 |
| 获取历史版本 | GET | `/api/sheets/{id}/versions` | 版本回溯 |
| RAG 查询 | POST | `/api/rag/query` | 自然语言查询 |
| 公式验证 | POST | `/api/formula/validate` | 公式语法检查 |
| 导出表格 | POST | `/api/sheets/{id}/export` | 脱敏后导出 |
| 审计日志查询 | GET | `/api/audit/logs` | 管理员专用 |

## 附录 A: 决策记录 (ADR)

### ADR-001: 为什么选择 Yjs 而非 OT

- **状态**: Accepted
- **日期**: 2026-05-07
- **背景**: 多人协作需要冲突解决机制
- **选项**: OT (Operational Transformation) vs CRDT (Yjs)
- **决策**: 选择 Yjs (CRDT)
- **理由**: 
  - 无需中心服务器协调冲突
  - 天然支持离线编辑和自动合并
  - 与 vxe-table 双向绑定简单
- **后果**: 需接受 CRDT 的存储开销（约 20% 额外元数据）

### ADR-002: 为什么选择 Supabase 本地化

- **状态**: Accepted
- **日期**: 2026-05-07
- **背景**: 需要私有化部署的后端基础设施
- **选项**: 自研后端 vs Supabase 本地化 vs 其他 BaaS
- **决策**: Supabase 本地化 (Docker Compose)
- **理由**:
  - 一键部署，降低运维成本
  - 内置 Auth、Realtime、Storage、PostgreSQL
  - 社区活跃，文档完善
- **后果**: 需学习 Supabase 特有 API（如 RLS 策略）
