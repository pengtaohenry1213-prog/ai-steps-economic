## 1. 目标与范围

### 1.1 目标
定义系统需满足的等保（等级保护）合规要求，明确数据分类分级标准、安全控制措施、审计留存期限、合规检查清单，确保系统通过等保二级/三级测评。

### 1.2 范围
- ✅ 等保二级/三级要求映射
- ✅ 数据分类分级标准
- ✅ 安全控制措施（技术+管理）
- ✅ 审计日志留存期限
- ✅ 合规检查清单与测评准备

### 1.3 不在范围内
- ❌ 等保测评机构对接（由合规团队负责）
- ❌ 物理环境安全（机房、门禁）

---

## 2. 术语定义

| 术语 | 定义 |
|------|------|
| 等保 | 网络安全等级保护，中国信息安全基本制度 |
| 等保二级 | 适用于一般信息系统，自主保护级 |
| 等保三级 | 适用于重要信息系统，监督保护级 |
| 数据分级 | 根据数据敏感程度划分保护等级 |
| 安全域 | 逻辑隔离的网络区域，如 DMZ、内网、管理区 |
| 三员管理 | 系统管理员、安全管理员、安全审计员分离 |

---

## 3. 设计原则

| 原则 | 说明 |
|------|------|
| **合规先行** | 系统设计阶段即考虑等保要求，而非事后补全 |
| **最小够用** | 根据业务实际确定等保级别（建议二级起步，三级为目标） |
| **技管结合** | 技术措施（加密、审计）+ 管理措施（制度、流程）并重 |
| **持续合规** | 合规不是一次性工作，需持续监控和改进 |

## 4. 详细设计

### 4.1 等保要求映射

#### 4.1.1 等保二级要求（当前必须满足）

| 安全层面 | 控制点 | 技术要求 | 本系统实现 |
|---------|--------|---------|-----------|
| **安全物理环境** | 物理位置、访问控制、防盗窃 | 机房环境 | 由运维负责 |
| **安全通信网络** | 网络架构、通信传输、可信验证 | 传输加密 | TLS 1.3 |
| **安全区域边界** | 边界防护、访问控制、入侵防范 | 网络隔离 | 内网部署 |
| **安全计算环境** | 身份鉴别、访问控制、安全审计 | 多因素认证 | JWT + RBAC + 审计日志 |
| **安全管理中心** | 系统管理、审计管理、安全管理 | 三员分离 | admin/auditor/operator 角色 |
| **安全管理制度** | 安全策略、管理制度、制定发布 | 制度文档 | 需补充 |
| **安全管理机构** | 岗位设置、人员配备、授权审批 | 组织架构 | 需明确 |
| **安全管理人员** | 人员录用、人员离岗、安全意识 | 培训记录 | 需补充 |
| **安全建设管理** | 定级备案、安全方案、产品采购 | 等保备案 | 需启动 |
| **安全运维管理** | 环境管理、资产管理、介质管理 | 运维流程 | 需补充 |

#### 4.1.2 等保三级增强要求（远期目标）

| 控制点 | 二级要求 | 三级增强 |
|--------|---------|---------|
| 身份鉴别 | 用户名+密码 | **+ 双因素认证（2FA）** |
| 访问控制 | RBAC | **+ 细粒度权限（行列级）** |
| 安全审计 | 操作日志 | **+ 日志防篡改 + 异地备份** |
| 入侵防范 | 基础防护 | **+ WAF + 入侵检测系统** |
| 数据完整性 | 传输加密 | **+ 存储加密 + 数字签名** |
| 数据保密性 | 敏感数据保护 | **+ 全量数据加密 + 密钥管理** |
| 备份恢复 | 定期备份 | **+ 异地灾备 + RTO<4h** |

### 4.2 数据分类分级标准

#### 4.2.1 数据分类

| 分类 | 说明 | 示例 |
|------|------|------|
| **用户数据** | 系统用户信息 | 账号、密码、角色、部门 |
| **业务数据** | 表格核心数据 | 单元格值、公式、格式 |
| **日志数据** | 系统运行记录 | 操作日志、审计日志、错误日志 |
| **配置数据** | 系统配置信息 | 权限配置、脱敏规则、RAG 配置 |
| **知识数据** | RAG 向量数据 | 向量 Embedding、Chunk 索引 |

#### 4.2.2 数据分级（五级）

| 级别 | 标识 | 定义 | 示例 | 保护措施 |
|------|------|------|------|---------|
| **L1 公开** | 🟢 | 可公开访问的数据 | 增值税税率表、帮助文档 | 无需特殊保护 |
| **L2 内部** | 🟡 | 企业内部共享 | 部门销售汇总、培训材料 | 内部访问控制 |
| **L3 敏感** | 🟠 | 含个人信息或财务明细 | 员工工资、客户名单、纳税申报 | **必须脱敏 + 严格权限** |
| **L4 机密** | 🔴 | 核心商业机密 | 并购方案、年度预算、审计底稿 | **加密存储 + 最小授权** |
| **L5 绝密** | ⚫ | 国家秘密或最高商业机密 | 涉及国家安全的财税数据 | **物理隔离 + 专人管理** |

#### 4.2.3 数据分级处理矩阵

| 处理环节 | L1 | L2 | L3 | L4 | L5 |
|---------|----|----|----|----|----|
| 存储 | 普通 | 普通 | **加密** | **加密+签名** | **物理隔离** |
| 传输 | HTTP | HTTPS | **TLS 1.3** | **TLS 1.3+证书绑定** | **专线** |
| 展示 | 明文 | 明文 | **脱敏** | **脱敏+水印** | **禁止展示** |
| 导出 | 允许 | 允许 | **脱敏+审批** | **审批+水印+加密** | **禁止导出** |
| 备份 | 普通 | 普通 | **加密备份** | **加密+异地** | **专人操作** |
| 销毁 | 普通删除 | 普通删除 | **安全擦除** | **安全擦除+审计** | **物理销毁** |
| 留存期限 | 无要求 | 3 年 | **5 年** | **10 年** | **永久** |

### 4.4 三员管理

```typescript
// 三员分离：系统管理员、安全管理员、安全审计员
enum AdminRole {
  SYSTEM_ADMIN = 'system_admin',      // 系统管理员：用户管理、配置管理
  SECURITY_ADMIN = 'security_admin',  // 安全管理员：权限分配、安全策略
  AUDIT_ADMIN = 'audit_admin',        // 安全审计员：查看日志、合规检查
}

// 权限互斥：同一用户不能同时拥有两个管理员角色
function checkRoleConflict(userRoles: string[]): boolean {
  const adminRoles = [
    AdminRole.SYSTEM_ADMIN,
    AdminRole.SECURITY_ADMIN,
    AdminRole.AUDIT_ADMIN,
  ];
  const userAdminRoles = userRoles.filter(r => adminRoles.includes(r));
  return userAdminRoles.length <= 1;
}

// 三员职责矩阵
const ADMIN_RESPONSIBILITIES = {
  [AdminRole.SYSTEM_ADMIN]: [
    '用户账号管理（创建/禁用/重置密码）',
    '系统配置管理',
    '备份与恢复操作',
    '性能监控与优化',
  ],
  [AdminRole.SECURITY_ADMIN]: [
    '权限策略制定与分配',
    '安全策略配置',
    '漏洞扫描与修复',
    '安全事件处置',
  ],
  [AdminRole.AUDIT_ADMIN]: [
    '审计日志查看与分析',
    '合规检查与报告',
    '异常行为调查',
    '定期安全审计',
  ],
};
```

### 4.5 审计日志留存期限

| 日志类型 | 留存期限 | 存储位置 | 访问权限 |
|---------|---------|---------|---------|
| 登录/登出日志 | **180 天** | PostgreSQL | 审计员 |
| 操作日志（CRUD） | **365 天** | PostgreSQL + 对象存储 | 审计员 |
| 数据变更日志（前后值） | **365 天** | PostgreSQL | 审计员 |
| RAG 查询日志 | **365 天** | PostgreSQL | 审计员 |
| 安全日志（攻击/异常） | **永久** | PostgreSQL + 异地备份 | 审计员 + 安全管理员 |
| 导出日志 | **永久** | PostgreSQL | 审计员 |
| 系统错误日志 | **90 天** | 文件系统 | 系统管理员 |

### 4.6 合规检查清单

#### 4.6.1 等保二级检查清单

```
□ 身份鉴别
  □ 用户身份唯一标识
  □ 密码复杂度策略（长度≥8，含大小写+数字+特殊字符）
  □ 登录失败处理（5次锁定30分钟）
  □ 会话超时（2小时无操作自动登出）
  □ 密码定期更换（90天）

□ 访问控制
  □ 角色分离（admin/editor/viewer）
  □ 权限最小化
  □ 敏感操作二次确认
  □ 离职账号及时禁用

□ 安全审计
  □ 审计范围覆盖所有用户
  □ 审计记录包含用户、时间、操作、结果
  □ 审计记录防篡改
  □ 审计记录留存≥180天

□ 数据安全
  □ 传输加密（HTTPS/TLS）
  □ 敏感数据存储加密
  □ 数据备份（每日全量）
  □ 备份恢复测试（每季度）

□ 入侵防范
  □ 输入校验（防 SQL 注入、XSS）
  □ 软件版本及时更新
  □ 漏洞扫描（每月）
  □ 恶意代码防范

□ 管理制度
  □ 信息安全管理制度
  □ 数据分级管理制度
  □ 人员安全管理制度
  □ 应急响应预案
```

#### 4.6.2 等保三级增强检查清单

```
□ 身份鉴别
  □ 双因素认证（2FA）
  □ 生物特征认证（可选）
  □ 登录异常告警

□ 访问控制
  □ 细粒度权限（行列级）
  □ 权限定期复核（每季度）
  □ 特权账号管理

□ 安全审计
  □ 审计日志集中管理
  □ 审计日志实时分析
  □ 审计日志异地备份
  □ 审计员独立账号

□ 数据安全
  □ 全量数据加密（AES-256）
  □ 密钥管理系统（KMS）
  □ 数据脱敏自动化
  □ 数据防泄漏（DLP）

□ 入侵防范
  □ Web 应用防火墙（WAF）
  □ 入侵检测系统（IDS）
  □ 入侵防御系统（IPS）
  □ 安全态势感知

□ 备份恢复
  □ 异地灾备
  □ RTO < 4 小时
  □ RPO < 1 小时
  □ 灾备演练（每半年）
```

## 5. 合规测评准备

### 5.1 测评前准备材料

| 材料 | 内容 | 责任人 |
|------|------|--------|
| 定级报告 | 系统定级理由、业务描述、影响分析 | 安全管理员 |
| 备案证明 | 公安机关备案回执 | 安全管理员 |
| 差距分析 | 现状与等保要求的差距 | 安全管理员 |
| 整改报告 | 差距项整改情况 | 系统管理员 |
| 管理制度 | 安全管理制度汇编 | 安全管理员 |
| 技术文档 | 网络拓扑、系统架构、数据流 | 技术负责人 |
| 测评报告 | 第三方测评机构出具的报告 | 测评机构 |

### 5.2 测评流程

```
定级 → 备案 → 建设整改 → 等级测评 → 监督检查
 │      │        │           │          │
 ▼      ▼        ▼           ▼          ▼
编写    公安    差距分析     第三方     每年
定级    机关    整改实施     测评机构   复查
报告    备案    自查完善     现场测评
```
