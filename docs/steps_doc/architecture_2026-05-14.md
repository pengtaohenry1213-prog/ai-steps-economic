## 二、项目背景与目标

### 2.1 背景

当前系统（v1）已实现经济模型系统的核心功能，包括模型管理、版本控制、公式计算和Excel导入导出。但存在以下局限：

| 局限 | v1现状 | 业务影响 |
|------|--------|----------|
| 公式引擎自研 | FunctionCore + Kahn拓扑排序 | 维护成本高，XIRR等复杂函数算法不精确 |
| 单人编辑 | 无实时协作能力 | 多部门协作效率低 |
| 后端Mock | 基于Nitro | 无法支持真实业务扩展 |

v2采用全新设计方案：**HyperFormula + Yjs CRDT + Supabase架构**，支持多人协作和RAG智能助手。

### 2.2 当前问题（v1）

1. 自研公式引擎维护成本高，财务函数（XIRR/XNPV/NPV/IRR）算法精度不足
2. 单人编辑模式无法满足多部门协作需求
3. 后端Mock架构无法支持真实业务扩展
4. 安全机制依赖前端权限控制，缺乏服务端审计

### 2.3 项目目标

| 目标 | 说明 | 量化指标 |
|------|------|----------|
| **公式零误差** | HyperFormula确保财务公式100%准确 | XIRR/XNPV/NPV/IRR误差率<0.01% |
| **协作无冲突** | Yjs CRDT支持多人同时编辑 | 支持5+用户同时在线 |
| **内网可运行** | Supabase本地化部署，无外网依赖 | Docker一键部署 |
| **数据零泄漏** | 敏感字段全程脱敏 | 字段脱敏覆盖率100% |
| **审计可追溯** | 完整操作日志记录 | 日志保留≥1年 |

### 3.3 技术方案要点

**公式引擎混合方案**（ADR-002已决策）：

```
HyperFormula原生函数: XIRR, SUM, MAX, MIN, IF, AVERAGE等基础函数
+ v1自研补充: XNPV (HF没有), NPV (HF不支持日期数组), IRR (算法不同)
```

```typescript
// HyperFormula配置
const hf = HyperFormula.buildEmpty({
  licenseKey: 'gpl-v3',
  functions: {
    'NPV': { internal: false },  // 禁用HF版本
    'IRR': { internal: false },  // 禁用HF版本
  },
});
// 补充v1自定义函数
hf.registerFunction('XNPV', v1_xnpv_impl);
hf.registerFunction('NPV', v1_npv_impl);
hf.registerFunction('IRR', v1_irr_impl);
```

## 2. 项目背景与目标

### 2.1 背景

经济模型系统v1已实现核心功能（模型管理、版本控制、公式计算、Excel导入导出），但存在以下局限：

| 局限 | v1现状 | 业务影响 |
|------|--------|----------|
| 公式引擎自研 | FunctionCore + Kahn拓扑排序 | 维护成本高，XIRR等复杂函数算法不精确 |
| 单人编辑 | 无实时协作能力 | 多部门协作效率低 |
| 后端Mock | 基于Nitro | 无法支持真实业务扩展 |
| 安全机制 | 依赖前端权限控制 | 缺乏服务端审计 |

### 2.2 升级目标

- **升级公式引擎**：采用HyperFormula，提升计算精度
- **实现多人协作**：基于Yjs CRDT，支持5+用户同时在线编辑
- **构建真实后端**：基于Supabase，支持本地化部署，无外网依赖
- **完善安全机制**：敏感数据脱敏、操作日志审计、RBAC权限矩阵
- **预留AI能力**：RAG智能助手自然语言查询
