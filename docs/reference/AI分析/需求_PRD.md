### 2.5 T1-T4项目类型适配说明

本PRD模板支持T1-T4四种项目类型，各类型的编写重点如下：

| 项目类型 | 核心章节 | 编写重点 |
| --- | --- | --- |
| **T1 创新型** | 项目概述 | 重点写"验证目标"和"失败标准"，范围可以模糊；用户故事少而精；非功能需求宽松；里程碑以周为单位 |
| **T2 稳定型** | 技术约束、性能需求 | 重点写"技术约束"和"交付时间"，范围要明确；重点关注性能和兼容性需求 |
| **T3 成熟型** | 功能需求、可维护性 | 重点写"标准化要求"和"效率目标"，范围要详细；重点关注可维护性和标准化需求 |
| **T4 核心系统升级** | 兼容性约束、数据需求 | 重点写"兼容性约束"和"业务连续性要求"；非目标要明确"不修改任何现有业务逻辑"；增加"一致性验收标准"和"数据迁移需求" |

> **T4专用约束**：
> - 计算一致性：所有公式结果与v1误差 < 0.0001%
> - 数据一致性：迁移/双写/回滚数据零丢失
> - 业务一致性：页面、交互、权限、状态机与v1完全一致

## PRD编写原则

1. **清晰准确**：语言简洁明了，没有歧义，避免模糊描述
2. **可验证**：所有需求都要有可量化的验收标准
3. **可追溯**：每个需求都要有明确的来源和责任人
4. **完整性**：覆盖所有核心业务场景和异常情况
5. **一致性**：PRD内部以及与其他文档之间保持一致
