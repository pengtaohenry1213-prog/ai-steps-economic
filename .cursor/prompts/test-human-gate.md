# Human Gate：Test 测试验收

## 触发时机

- 测试报告提交时
- 发布前质量评审时
- 缺陷关闭前复验时

## Gate 检查项

### 1. 用例覆盖

- [ ] **核心场景用例 100%** 覆盖
- [ ] **非核心场景 ≥95%** 覆盖
- [ ] 含正向、逆向、边界、异常场景
- [ ] 覆盖目标与发布范围一致

### 2. 缺陷管理

- [ ] 缺陷分级明确（P0/P1/P2/P3）
- [ ] 缺陷可复现（步骤清晰）
- [ ] 缺陷有证据（截图/日志摘要）
- [ ] P0/P1 缺陷已全部修复或已有应对方案

### 3. 报告质量

- [ ] 包含范围与环境说明
- [ ] 通过率摘要清晰
- [ ] **未通过项列表**：级别/影响/建议
- [ ] 发布建议明确

### 4. 回归与冒烟

- [ ] 回归覆盖修改点 + 合理关联面
- [ ] 冒烟验证主路径通过

## 优先级定义

| 级别 | 定义 | 通过要求 |
|------|------|----------|
| **P0** | 核心不可用或数据严重错误，阻塞发布 | 必须 100% 通过 |
| **P1** | 主路径受损或高风险逻辑错误 | 必须 100% 通过 |
| **P2** | 非主路径缺陷 | 允许遗留，需评审 |
| **P3** | 文案、轻微视觉、体验类 | 可遗留至下版本 |

## 输出结果

| 决策 | 条件 |
|------|------|
| **PASSED** | P0/P1 全部通过，总通过率≥95% |
| **CONDITIONAL** | P0/P1 通过，非核心项未达标，有整改计划 |
| **FAILED** | P0/P1 有未通过项 |

## 闭环要求

- FAILED 状态必须跟踪至 P0/P1 全部解决
- CONDITIONAL 需明确整改期限
- 发布决策需 Test Lead + PM 双方确认

## 禁止

- 为凑覆盖率编造不可执行用例
- 级别含糊或「全局必须 100%」脱离上下文
- 缺陷描述无法复现
