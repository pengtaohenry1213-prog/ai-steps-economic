## 二、技术选型要点

### 2.1 医疗信息标准

| 标准 | 用途 | 说明 |
|-----|------|------|
| **HL7 V2.4** | 消息交换 | 传统HIS广泛支持 |
| **HL7 FHIR** | 现代API | 未来趋势 |
| **DICOM** | 影像存储传输 | PACS核心标准 |
| **ICD-10** | 疾病编码 | 诊断编码 |
| **LOINC** | 检验编码 | 检验项目编码 |

### 2.2 技术架构建议

| 层级 | 技术 | 说明 |
|-----|------|------|
| **应用平台** | 优先成熟HIS | 东软、卫宁、东华等 |
| **集成引擎** | InterSystems / Mirth | HL7消息路由 |
| **影像平台** | Oviyam / DCM4CHE | DICOM查看/存储 |
| **数据库** | Oracle / SQL Server | 医疗行业主流 |
| **缓存** | Redis | 会话缓存 |

## 四、安全架构

### 4.1 等保三级要求

| 系统 | 安全要求 |
|-----|---------|
| **边界防护** | 防火墙、网闸隔离 |
| **访问控制** | 三权分立、最小权限 |
| **入侵防范** | IDS/IPS |
| **审计追溯** | 日志完整保留6个月 |
| **数据安全** | 加密、备份、脱敏 |

### 4.2 患者隐私保护

```
┌─────────────────────────────────────────────────────────────┐
│                    患者隐私保护措施                           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  数据脱敏                                                  │
│  ├── 展示脱敏：姓名*、身份证号****                           │
│  ├── 接口脱敏：只返回必要字段                               │
│  └── 日志脱敏：日志中隐藏敏感信息                           │
│                                                             │
│  权限控制                                                  │
│  ├── 角色权限：护士、医生、管理员                           │
│  ├── 数据权限：只看本科室患者                               │
│  └── 操作审计：所有访问记录留痕                             │
│                                                             │
│  传输安全                                                  │
│  ├── HTTPS 加密传输                                         │
│  ├── VPN 专线                                              │
│  └── 端到端加密（重要数据）                                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.3 危急值闭环

```
医生开医嘱 → LIS检验 → 结果审核 → 危急值判断 → 告警通知 → 医生确认 → 记录归档
```

## 五、高可用架构

### 5.1 双机热备

| 组件 | 高可用方案 |
|-----|---------|
| **数据库** | Oracle RAC / SQL Server AlwaysOn |
| **应用** | 双机热备 + 负载均衡 |
| **存储** | SAN 存储双活 |

### 5.2 容灾架构

| 级别 | 方案 | RPO | RTO |
|-----|------|-----|-----|
| **本地容灾** | 双机房部署 | 15分钟 | 30分钟 |
| **异地容灾** | 同城灾备中心 | 1小时 | 1小时 |
| **数据备份** | 异地备份 | 1天 | 天级 |
