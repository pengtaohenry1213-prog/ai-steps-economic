## 三、匹配方法（待选定）

| 方案 | 实现方式 | 工作量 | 适用场景 |
| --- | --- | --- | --- |
| A（推荐） | LLM 直接判断 | 低 | 快速验证 |
| B | Embedding 向量匹配 | 中 | 提升精度 |
| C | 关键词 + Embedding 混合 | 中 | 兼容传统搜索 |

推荐方案A：LLM 直接判断，TypeScript + NestJS

逻辑：用户需求 → LLM 判断（T1-T14 哪个 + 哪个行业）→ 输出组合

```bash
用户输入："我们是个三甲医院，要开发一个门诊管理系统"
     ↓
LLM判断：T3（成熟项目）+ 医疗健康行业
     ↓
输出：《T3开发策略》+ 《医疗健康行业适配要点》
```

实现方式：

1. 写一个 system prompt，告知 LLM 有哪些策略和行业可选 [buildStrategyMatchingSystemPrompt](../app/src/prompts/strategy-matching-prompt.ts)

2. 用户输入需求时，LLM 直接输出匹配结果

3. 可以用 few-shot examples 提升准确率

优点：实现最简（100行代码）、理解语义、处理模糊表述

缺点：依赖 LLM 能力，结果不够稳定时可加 fallback
