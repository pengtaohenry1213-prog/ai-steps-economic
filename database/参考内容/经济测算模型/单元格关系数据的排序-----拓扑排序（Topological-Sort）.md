## 单元格关系数据的排序 --- 拓扑排序

拓扑排序应用于 有向无环图`DAG`，其中每条边表示一个 **依赖关系**：`节点A`依赖于`节点B` => 图中从`B`指向`A`画一条边（`B → A`）。

使用拓扑排序来排序单元格的计算顺序，应该以 **直接引用** 为依据，而不是 **间接引用**。
构图方式: 遍历每个单元格的公式, 找出所有被直接引用的单元格，对每个被引用的单元格 X，添加边. 
`{ source: "X", target: "当前单元格" }`


比如：
| 单元格 | 公式       | 直接依赖   |
| --- | -------- | ------ |
| A1  | =B1 + C1 | B1, C1 |
| B1  | =D1      | D1     |
| C1  | =5       | 无      |
| D1  | =2       | 无      |

构建依赖图：
B1 → A1 （A1依赖B1）
C1 → A1 （A1依赖C1）
D1 → B1 （B1依赖D1）

```
D1 → B1 → A1
        ↘
         C1

D1
 ↓
B1      C1
 ↓      ↓
   →  A1
```



> 解释图中箭头含义：
X → Y 表示 Y 依赖于 X，即在计算 Y 之前必须先计算 X。

> 为什么不能用 **间接引用** ？
你应该根据这些 **直接依赖** 关系构建有向图，然后使用拓扑排序。
**间接引用** 是由多个直接依赖构成的传递关系。如果你用 **间接引用** 构建图，会导致边数膨胀、不必要的复杂度，并可能形成“虚假的环”，使得原本合法的依赖关系图无法拓扑排序。
