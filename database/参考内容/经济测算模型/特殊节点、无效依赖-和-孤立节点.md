## 拓扑排序方法, 要求: 
1. 特殊节点不纳入依赖图;
2. 排除“无效依赖”;
3. 孤立节点, 可以保留，但要确保不会被误判为环. 区分真正的环和孤立节点, 如果节点的 dependencies 和 dependents 都为空，就是孤立节点，不应算作环。
4. 检查断链, 某个单元格的 dependencies 指向了一个不存在的节点;
5. 真正的环是：依赖链中存在回路，即A依赖B，B依赖C，C又依赖A。

特殊节点会被错误地纳入依赖图，影响后续拓扑排序和循环依赖检测。
无效依赖（如指向不存在节点的依赖）会导致入度统计异常，影响排序和环检测。
孤立节点（无依赖也无被依赖）如果不处理，可能会被误判为异常节点。

解决建议
1. 在getCellRelationData中处理特殊节点
  过滤dependencies和dependents中的特殊节点
  在生成每个节点的dependencies和dependents时，使用isSpecialData过滤掉特殊节点。
2. 处理无效依赖
  只保留依赖于实际存在于cellsInfo或relationData中的节点
  在收集依赖时，判断目标节点是否存在。
3. 处理孤立节点
  孤立节点可以保留，但要确保不会被误判为环
  孤立节点的dependencies和dependents都应为空数组。
4. 检查断链
  某个单元格的 dependencies 或 dependents 指向了一个不存在的节点（即该 id 不在 cellsInfo 或 relationData 中）。
  这会导致依赖图不完整，影响后续的拓扑排序、循环依赖检测、批量计算等。


---

### 区分真正的环和孤立节点，比如：
如果节点的 dependencies 和 dependents 都为空，就是孤立节点，不应算作环。
如果节点的 dependencies 不为空，但依赖的节点都已被处理，也不应算作环。

如何优化判定逻辑？
  1. 真正的环判定
    真正的环是：依赖链中存在回路，即A依赖B，B依赖C，C又依赖A。
    你可以用DFS或Tarjan算法检测强连通分量，或者在BFS拓扑排序后，只输出依赖链中确实有回路的节点。
  2. 断链判定
    断链是：依赖的节点在数据中不存在，你已经在依赖图构建时做了过滤和警告。
  3. 孤立节点判定
    孤立节点（无依赖、无被依赖）应直接跳过，不应算作环。

## 原因分析

### 1. 为什么 C10000A0439-2028 被判定为循环依赖节点？

- 在拓扑排序算法中，如果某个节点的入度在排序结束后仍大于0，说明它在一个“环”里（即循环依赖）。
- 但实际上，**只要有环，环上的所有节点的入度都不会归零**，所以它们都会被列为“循环依赖节点”。
- 但如果您的数据本身没有环，或者只有很少的环，而结果却有很多节点被判定为循环依赖节点，说明算法实现或依赖图构建有问题。

### 2. topologicalSortCellRelationData方法是否正确？

#### 可能存在的问题：
- **依赖图构建不准确**：有可能把一些本不应参与环检测的节点（如特殊数据、孤立节点、无效依赖）也纳入了检测。
- **特殊数据过滤不彻底**：虽然您已过滤特殊前缀和_LP结尾，但如果依赖链中有“断链”或“无效节点”，也会导致入度无法归零。
- **依赖数据本身有误**：比如有些节点的dependencies里写了不存在的节点，或者有自依赖等。

#### 检查建议：
1. **确认依赖图构建时，所有dependencies都已正确过滤特殊数据和无效节点。**
2. **确认所有节点的dependents和dependencies是一致的（即A依赖B，B的dependents里有A）。**
3. **确认数据中没有“断链”或“孤立节点”被误判为环。**
4. **可以在拓扑排序前后，打印所有入度>0的节点的依赖链，人工核查是否真的成环。**

### 3. 为什么会“感觉没有这么多循环依赖节点”？

- 很多时候，实际业务数据中环很少，若检测结果一大堆，通常是依赖图构建或过滤有误。
- 也有可能是某个环很大，导致环上的所有节点都被判定为“循环依赖节点”。

## 建议的排查步骤

1. **在topologicalSortCellRelationData方法中，打印所有入度>0节点的依赖链，人工核查。**
2. **确认isSpecialData过滤逻辑是否覆盖所有特殊情况。**
3. **检查依赖数据源，确认没有无效依赖或自依赖。**
4. **可用如下代码辅助调试：**

```js
// 在检测到循环依赖时，打印每个节点的依赖链
cycleNodes.forEach(nodeId => {
  const chain = [];
  let current = nodeId;
  const visited = new Set();
  while (current && !visited.has(current)) {
    chain.push(current);
    visited.add(current);
    const deps = (cellRelationData[current]?.dependencies || []).filter(dep => !isSpecialData(dep));
    current = deps[0]; // 只跟第一个依赖走一条链
  }

});
```
