 关键差异解读

 ① Luckysheet vs HyperFormula+vxe-table

 Luckysheet 自带 UI 表格渲染（Excel-like），一步到位；HyperFormula 只是引擎需要配合 vxe-table 才能有
 UI。公式计算能力两者都不错。

 ② 多人协作——OT 算法是最大新增复杂度

 v2 现有 Supabase Realtime 是基于 PostgreSQL 行级锁 + Broadcast。Luckysheet 的协作是 Operation Transformation (OT)
 算法，两者实现路径完全不同。用户确认协作为必须实现项，所以 Phase 3 是绕不开的。

 3.2 架构方案：新建独立 App（推荐）

 方案 A（执行方案）：新建 apps/luckysheet-demo/
 - 独立于现有 MVT 代码，不影响 v2 现有功能
 - 单独安装 Luckysheet、xlsx 等新依赖
 - 独立数据库表（cells/formulas）
 - 复用 v2 的 pnpm workspace 配置和 Supabase 客户端

 方案 B：在 apps/web/ 内新建视图
 - 不推荐，两个技术栈并存增加复杂度

 四、实施路径（三阶段）

 Phase 1：基础能力（独立 App）

 新建 apps/luckysheet-demo/

 - [ ] 初始化 Vue3 + TypeScript + Vite 项目（复用 v2 workspace 配置）
 - [ ] 安装依赖：luckysheet、xlsx、@supabase/supabase-js、element-plus
 - [ ] 封装 Luckysheet Vue3 组件（隔离 DOM 依赖）
 - [ ] Excel 导入：xlsx 解析 → luckyexcel → Luckysheet celldata
 - [ ] Excel 导出：Luckysheet → xlsx 生成文件流触发下载
 - [ ] 验证 Luckysheet 在 Vue3+Vite 下稳定运行

 Phase 2：算法模块

 - [ ] 自定义公式注册到 luckysheet.functions
 - [ ] 拓扑排序（公式依赖排序，确保按依赖层级计算）
 - [ ] DFS 循环引用检测（追踪引用路径，定位循环节点）
 - [ ] Gauss-Seidel 不动点迭代（循环计算，差值 < 阈值如 1e-6 终止）
 - [ ] 阈值配置 UI（Element Plus 弹窗让用户自定义阈值）

 Phase 3：实时协作（必须实现）

 - [ ] cells/formulas 表 DDL 设计
 - [ ] Supabase Realtime Channel 配置
 - [ ] OT（Operation Transformation）算法实现或引入 ot.js / yjs
 - [ ] 多用户光标同步（Supabase Broadcast）
 - [ ] 协作冲突处理（OT变换 vs 行级锁）
 - [ ] 2秒去重窗口 + 3秒回声防止（避免 UI 闪烁）
