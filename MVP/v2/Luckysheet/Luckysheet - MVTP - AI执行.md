注：我是通过 `http://localhost:3008` 访问 `/Users/taopeng/workspace/AI_2026/ai-steps-economic/v2/apps/luckysheet-demo`

### 修复内容

- excelExport.ts：直接遍历 Luckysheet 二维数组，取 cell.v?.v 作为单元格值
- LuckysheetWrapper.vue：导出时传 data 而非 cells（字段名对齐）

> 问题根因：Luckysheet 的 getAllSheets().data 是稀疏二维数组，data[0][0] 对应 (r=0,c=0) 位置的单元格对象
{r,c,v:{v:...}}。之前错误地从 cell.r/c 取行列值然后用 encode_cell
构造地址，但实际上二维数组的索引就是行列位置，直接遍历取值即可。
> 导出的Excel文件里还是没数据。

> 修复内容：

- LuckysheetCell 接口去掉 r, c 字段（Luckysheet 的 data 二维数组索引本身就是行列，cell 对象里没有 r/c）
- 取值优先用 cell.v，其次 cell.m（m 是 Luckysheet 的格式化值）

  ---
  关键决策因素
  
  选 Supabase Realtime 如果：

  ✅ 优先验证协作功能本身，而非技术实现
  ✅ 接受最终一致性（行级锁）
  ✅ 数据量 < 1000 并发编辑/秒
  ✅ 需要数据库持久化
  ✅ 未来可能迁移到 Supabase 云端
  ✅ 团队熟悉 Supabase

  选 yjs + y-webrtc 如果：

  ✅ 优先数据一致性（多设备同时编辑不丢数据）
  ✅ 需要离线编辑支持
  ✅ 接受 signaling 部署成本
  ✅ 优先网络延迟 < 5ms
  ✅ 不需要数据库持久化（可叠加 Supabase 做归档）
  ✅ 未来可能扩展到大规模用户
