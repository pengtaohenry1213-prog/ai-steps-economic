# W1-W4 个人复盘

> 私人复盘，写给自己看 | 生成时间：2026-06-04

---

## 一、这次合并项目给我最大的收获

### 1.1 「骨不能削足适履，皮能包骨」

这个判断框架帮我快速做出决策：项目 A 的策略匹配/增强是核心差异化能力（骨），项目 B 的 UI 和流程是皮。合并方向必须是 B→A，而不是 A→B。

这个原则以后遇到类似的技术选型也能用：**核心能力不能动，周围能力可以迁**。

### 1.2 ADR 是给未来的自己看的

ADR #001 写的时候觉得"这些决策不是很明显吗，为什么要记下来"。但到了写 ADR #002 的时候，发现 ADR #001 的内容已经有点模糊了。

所以 ADR 的价值不是"记录显而易见的事"，而是**给未来的自己一个快速找回上下文的方式**。以后做任何架构决策，都要养成写 ADR 的习惯。

### 1.3 PoC 的价值在于"验证最小可行"

W3 PoC 验证了项目 B 能独立跑通立项书生成。ACL 适配器虽然在，但没有集成到调用链。

一开始我有点"完美主义"，觉得 ACL 没集成就是 PoC 没完成。但其实 PoC 的目的是**验证最小可行性**，不是验证完整流程。

W4 再做 ACL 集成，这样分阶段执行更合理。

## 二、我对「项目合并」这件事的理解有什么变化

### 2.1 从「一次性替换」到「渐进式包裹」

之前我理解的项目合并是：找到两个系统的差异，然后选一个作为目标，把另一个的功能迁移过去。这个思路隐含了"最终状态是统一的"。

但 Strangler Fig 模式改变了这个认知：**合并不是替换，而是让新系统逐渐包裹老系统**。最终可能不是"统一"，而是"并存"。

### 2.2 从「技术决策」到「组织决策」

ADR #001 的替代方案里有一个是"共存（各自独立维护）"。我一开始觉得这个方案"不合理"是因为"维护两套代码库成本翻倍"。

但仔细想想，"成本翻倍"是技术视角。如果两个团队的节奏、技术栈差异很大，强行合并反而会带来组织风险。

技术决策和组织决策需要一起考虑。

## 三、W4 执行过程中我发现的新问题

### 3.1 ACL 转换的边界在哪里

ACL 适配器做了 `ProposalDocument ↔ ProposalContent` 的双向转换。但 B 的 `proposalContent` 支持灵活结构（字段可选、支持 string 或 array），A 的 `ProposalDocument` 是严格结构。

如果 A 生成的字段在 B 里找不到对应位置，会不会丢失信息？

目前的解决方案是：转换时做双向验证，丢字段时 warn + log。但这只是一个暂时的处理方式。

真正的问题是：**合并后的数据模型应该是什么**？ACL 只是临时桥接，最终可能需要统一 schema。

### 3.2 B 的 AI 服务和 A 的 SDK 如何共存

B 有自己的 AI 服务（Ollama/OpenAI 双模式），A 的 SDK 也是调用 AI 服务。合并后如何处理这个并行关系？

ADR #002 的决策是：ACL 双模式支持，B 独立生成时走简化模式，A 的 SDK 调用时走完整模式。但这只是技术上的妥协。

真正的问题是：**合并后应该只有一个 AI 服务入口**。这个需要在 W4 执行阶段再思考。

## 四、我对「AI 工程化」的理解有什么变化

### 4.1 AI 是手段，不是目的

这次合并项目，两个系统都以"AI 生成"为核心能力。但 AI 生成只是手段，真正的目的是"生成高质量的立项书/需求文档/架构文档"。

有时候 AI 生成的内容不一定符合预期，但通过 PoC 验证，可以知道 AI 能做到什么程度、不能做到什么程度。

### 4.2 Human Gate 的价值

项目 B 有 Human Gate 双审机制（H1/HG2）。之前我觉得这是"增加流程复杂度"。

但现在我理解这是**质量门禁**：AI 生成的内容可能有错误或偏差，Human Gate 可以在关键节点做人工审核，防止错误传递到下游。

AI 和 Human Gate 结合，才是可靠的工作流。

## 五、后续需要持续关注的

| 关注点 | 原因 | 时间节点 |
|--------|------|----------|
| ACL schema 统一 | 当前 ACL 是临时桥接，最终需要统一数据模型 | W4 之后 |
| AI 服务入口统一 | B 和 A 各有 AI 服务入口，合并后应该只有一个 | W4 执行阶段 |
| ADR #002 执行结果 | ADR 只是决策记录，需要验证执行效果 | W4 执行后 |
| PoC 扩展到其他模块 | 当前 PoC 只验证了立项书生成，需求/架构还没验证 | W5+ |

---

## 六、一句话总结

> **W1-W4 最大的收获不是"学会了三个模式"，而是建立了"用 ADR 记录决策、用 PoC 验证最小可行、用 Strangler Fig 渐进替换"的肌肉记忆。**
