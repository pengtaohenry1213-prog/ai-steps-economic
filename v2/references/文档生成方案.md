# 完整文档生成方案（6个服务）

## 一、核心链路

```
用户需求
    ↓
┌────────────────────────────────────────────────────────────┐
│  服务1：matchStrategyWithAIService                          │
│  输入：用户需求 → 输出：T3策略 + software行业 + 置信度     │
└────────────────────────────────────────────────────────────┘
    ↓
┌────────────────────────────────────────────────────────────┐
│  服务2：generateAllDeliverablesWithAIService                │
│  输入：匹配结果 → 单次AI调用 → 输出4个文档：              │
│    - strategy-T3-{timestamp}.md   开发策略                 │
│    - proposal-T3-{timestamp}.md  立项书（对齐立项.md格式）│
│    - requirements-T3-{timestamp}.md 需求文档（对齐PRD格式）│
│    - architecture-T3-{timestamp}.md 架构书（对齐架构设计.md格式）│
└────────────────────────────────────────────────────────────┘
    ↓
┌────────────────────────────────────────────────────────────┐
│  服务3：generateStepDocumentsFromArchitecture              │
│  输入：architecture.md 内容                                 │
│  规则：按 scope.P0/P1 拆分，按 milestones 映射             │
│  输出：step1.md ~ stepN.md（每个含任务目标/详细说明/验收标准/里程碑映射）│
└────────────────────────────────────────────────────────────┘
    ↓
┌────────────────────────────────────────────────────────────┐
│  服务4：generateStepsDevDocument                           │
│  输入：所有 stepN.md                                         │
│  输出：steps-dev.md（阶段划分/执行顺序/角色分配/进度追踪） │
└────────────────────────────────────────────────────────────┘
```

---

## 二、6个服务职责

| # | 服务名 | 输入 | 输出 | 对齐参考 |
|---|--------|------|------|----------|
| 1 | matchStrategyWithAIService | 用户需求 | T策略 + 行业 + 置信度 | 现有 |
| 2 | generateAllDeliverablesWithAIService | 匹配结果 | 策略/立项书/需求/架构 | 立项.md / 需求_PRD.md / 架构设计.md |
| 3 | generateStepDocumentsFromArchitecture | architecture.md | step1.md ~ stepN.md | stepN生成规则.md |
| 4 | generateStepsDevDocument | 所有stepN.md | steps-dev.md | steps-dev.md |

## 三、Prompt 模板注入策略

不是让 AI 凭空生成，而是注入参考文档结构：

```
System Prompt 注入内容：
## 参考文档结构（来自 references/AI分析/）

### 立项书结构（立项.md）
- 一、时间线与工作边界（Mermaid Gantt）
- 二、项目基本信息表（名称/类型/周期/核心目标）
- 二、不可突破的核心约束（业务兼容性/技术风险/开发模式）
- 三、分阶段里程碑与Human Gate节点表（L2/L3/L4）
- 四、资源配置（人力+AI角色）
- 五、核心风险控制机制
- 六、验收标准（功能/性能/安全）

### 需求PRD结构（需求_PRD.md）
- 12章结构（项目概述/用户角色/功能需求/非功能需求/数据需求/测试策略）
- 功能表格（ID/优先级/业务规则/输入/输出/异常）
- T1-T4适配说明

### 架构设计结构（架构设计.md）
- 技术栈选型表（前端/后端/数据库/AI）
- 分层架构图（应用层/服务层/数据层）
- 模块划分表（前端模块/后端模块）
- API清单（认证/数据CRUD/AI对话/RAG搜索）
- 部署架构（dev/test/staging/prod）
- 监控体系（基础设施/应用性能/AI监控）

### StepN规则（stepN生成规则.md）
- P0[0]→step1, P0[1]+P0[2]→step2...
- 任务目标/详细说明/约束条件/验收标准/里程碑映射
- 合并策略：强依赖/同业务模块/v1复用>80%

### Steps-dev结构（steps-dev.md）
- 阶段划分表（零阶段/第一阶段/第二阶段/第三阶段）
- 执行顺序表（step0→step1→step6→...）
- 角色对应规则（Backend/Frontend/Frontend-UI/Frontend-集成）
- 进度追踪表（状态/角色/负责人/Plan文件/完成日期）
```

## 五、输出文件（完整链路）

```
{project}/
├── strategy-{type}-{timestamp}.md       # 开发策略（T3/software/85%）
├── proposal-{type}-{timestamp}.md      # 立项书
├── requirements-{type}-{timestamp}.md  # 需求文档（PRD）
├── architecture-{type}-{timestamp}.md   # 架构书
├── steps/                               # Step 任务文档
│   ├── step1.md                         # 任务目标 + 详细说明 + 验收标准
│   ├── step2.md
│   └── ...
└── steps-dev.md                         # 执行路线（阶段/顺序/角色/进度）
```
