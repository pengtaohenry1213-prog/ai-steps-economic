# T1 / T2 新项目架构设计模板（通用）

**适用项目**：T1 创新型新项目、T2 稳定型新项目（从0到1）
**设计原则**：业务优先、迭代友好、风险可控、可扩展
**版本**：v2.0（2026-05-15）现代化增强版

---

## 1. 架构概述

### 1.1 项目定位

- 项目类型：T1 创新型 / T2 稳定型新项目
- 核心目标：快速验证价值 / 稳定交付业务需求
- 架构风格：分层架构 + 模块化 + 可插拔
- 设计理念：简单清晰、易于迭代、便于测试、适合AI辅助开发

### 1.2 范围与边界

- 包含：前端、后端、数据存储、AI能力、公共能力、扩展能力
- 不包含：历史系统兼容、数据迁移、双写、灰度回滚（除非T2明确要求）

### 1.3 现代化要素（2026增强）

| 类别 | 建议引入 | 说明 |
|------|----------|------|
| AI 能力 | AI SDK（Vercel AI / OpenAI）| 智能助手、RAG 知识库 |
| 实时协作 | Yjs + WebSocket | 多人实时编辑 |
| 架构模式 | 事件驱动、Serverless | 异步解耦、按需扩展 |
| 监控 | 全链路追踪 | Skywalking / Jaeger / OpenTelemetry |

## 2. 业务目标与约束

### 2.1 业务目标

- 支持核心业务流程闭环
- 满足性能、并发、体验要求
- 可快速迭代、支持需求演进
- 符合团队技术栈与交付节奏
- 预留 AI 增强能力（如智能推荐、自动化分析）

### 2.2 约束条件

- 技术栈约束（框架/语言/中间件）
- 部署环境约束（云/内网/容器）
- 安全合规约束（认证、权限、隐私）
- 工期与里程碑约束
- AI 合规约束（如数据脱敏、模型选择）

## 4. 系统分层架构

### 4.1 经典分层

```
┌─────────────────────────────────────┐
│           前端应用层                │
│  (页面/组件/状态/路由/请求)         │
├─────────────────────────────────────┤
│           接口网关层                │
│  (API路由/鉴权/限流/日志)          │
├─────────────────────────────────────┤
│           业务服务层                │
│  (核心业务逻辑/领域服务)            │
├─────────────────────────────────────┤
│           数据访问层                │
│  (DAO/Repository/事务)             │
├─────────────────────────────────────┤
│           基础设施层                │
│  (DB/Redis/OSS/消息/监控)          │
└─────────────────────────────────────┘
```

### 4.2 事件驱动架构（可选）

```
┌─────────────┐    Event    ┌─────────────┐
│   Service   │ ──────────> │   Queue     │
│   (Publisher)│            │  (Kafka)    │
└─────────────┘             └──────┬──────┘
                                  │
                    ┌─────────────┼─────────────┐
                    │             │             │
                    ▼             ▼             ▼
             ┌──────────┐ ┌──────────┐ ┌──────────┐
             │ Service A│ │ Service B│ │ Service C│
             │(Consumer) │ │(Consumer) │ │(Consumer) │
             └──────────┘ └──────────┘ └──────────┘
```

### 4.3 AI 增强架构（可选）

```
┌─────────────────────────────────────────────────┐
│                  前端应用层                      │
│         (含 AI 对话组件 / RAG 搜索)             │
├─────────────────────────────────────────────────┤
│                  AI 服务层                      │
│  ┌─────────────┐  ┌─────────────┐            │
│  │  AI Gateway │  │  RAG Engine │            │
│  │ (模型路由)   │  │ (向量检索)   │            │
│  └─────────────┘  └─────────────┘            │
├─────────────────────────────────────────────────┤
│               传统业务服务层                    │
└─────────────────────────────────────────────────┘
```

### 6.2 ER图/关系设计

- 一对多、多对多
- 索引设计（普通索引 + 向量索引）
- 字段类型与约束
- 软删除与数据生命周期

### 6.3 向量数据设计（AI 场景）

```sql
-- 向量存储示例（pgvector）
CREATE TABLE documents (
  id UUID PRIMARY KEY,
  content TEXT,
  embedding vector(1536),  -- OpenAI text-embedding-3-small
  metadata JSONB,
  created_at TIMESTAMP
);

CREATE INDEX ON documents USING ivfflat (embedding cosine_ops);
```

## 7. API 设计

### 7.1 接口规范

- 统一请求/响应格式（RESTful / GraphQL）
- 错误码规范（业务错误码 + HTTP 状态码）
- 分页规范（Cursor / Offset）
- 权限控制规范（Scope + Resource）
- AI 特定接口（流式响应、Streaming）

### 7.2 核心接口清单

| 类别 | 接口示例 | 说明 |
|------|----------|------|
| 认证授权 | /auth/login, /auth/refresh | JWT + OAuth2 |
| 数据 CRUD | /api/v1/{resource} | 标准 REST |
| AI 对话 | /api/ai/chat, /api/ai/stream | 流式响应 |
| RAG 搜索 | /api/ai/search | 向量检索 |
| 文件处理 | /upload, /export | 大文件异步 |
| WebSocket | /ws/collab | 实时协作 |

### 7.3 AI 接口设计规范

```typescript
// 流式响应示例
POST /api/ai/chat
{
  "messages": [
    { "role": "user", "content": "..." }
  ],
  "stream": true,
  "context": { "document_ids": ["..."] }
}

// 响应（Server-Sent Events）
data: {"delta": "你好"}
data: {"delta": "，有什么"}
data: {"done": true}
```

## 8. 部署架构

### 8.1 环境规划

| 环境 | 用途 | 流量 |
|------|------|------|
| dev | 开发调试 | 内部 |
| test | 集成测试 | 内部 |
| staging | 预发布 | 少量外部 |
| prod | 生产环境 | 100% |

### 8.2 部署方式

| 组件 | 部署方案 | 说明 |
|------|----------|------|
| 前端 | Vercel / CDN / Docker | 静态托管或容器化 |
| 后端 | K8s / Docker Compose / Serverless | 按需选择 |
| 数据库 | 云托管 / 自建 | RDS / 自建 PG |
| 向量数据库 | Qdrant Cloud / 自建 | AI 场景 |
| 监控 | Prometheus + Grafana Cloud | 全链路追踪 |

### 8.3 CI/CD 流水线

```
代码提交 → Lint/TypeCheck → Unit Test → Build → Integration Test → Deploy
                                                          ↓
                                              Staging → E2E Test → Production
```

## 9. 监控与可观测性

### 9.1 监控体系

| 类型 | 工具 | 指标 |
|------|------|------|
| 基础设施 | Prometheus + Grafana | CPU/内存/磁盘/网络 |
| 应用性能 | APM / OpenTelemetry | 请求耗时、错误率 |
| 全链路追踪 | Jaeger / Zipkin | 请求链路、依赖分析 |
| 日志 | ELK / Loki | 日志聚合、检索 |
| AI 监控 | LangSmith / 自建 | Token 消耗、延迟、质量 |

### 9.2 告警规则

| 级别 | 条件 | 通知方式 |
|------|------|----------|
| P0 | 服务不可用 | 电话 + 短信 |
| P1 | 错误率 > 5% | 短信 + 邮件 |
| P2 | 延迟 > 1s | 邮件 |
| P3 | 异常趋势 | 邮件 |

## 10. 测试策略

### 10.1 测试金字塔

```
        ┌─────────────────┐
        │      E2E        │  ← 少量关键路径
       ┌┴─────────────────┴┐
       │    Integration    │  ← API 集成
      ┌┴───────────────────┴┐
      │        Unit          │  ← 大量单元测试
     ┌┴─────────────────────┴┐
```

### 10.2 测试类型

| 类型 | 工具 | 覆盖率目标 |
|------|------|------------|
| 单元测试 | Vitest / Jest | 80%+ |
| 集成测试 | Supertest / Playwright | 核心流程 |
| E2E 测试 | Playwright / Cypress | 关键路径 |
| AI 测试 | 人工评估 + 自动化评分 | 响应质量 |

### 10.3 AI 功能测试

| 测试维度 | 方法 | 指标 |
|----------|------|------|
| 功能正确性 | 单元测试 + 集成测试 | 通过率 |
| 响应质量 | 人工评估 + LLM-as-Judge | 满意度 |
| 性能 | 压测 | P95 < 2s |
| 安全 | Prompt 注入测试 | 无敏感泄露 |

## 12. 风险与缓解

| 风险类型 | 缓解措施 | 现代化工具 |
|----------|----------|------------|
| 需求迭代风险 | 模块化、低耦合 | 微前端 / 插件化 |
| 性能风险 | 缓存、异步、分页 | Redis / 消息队列 |
| 安全风险 | 鉴权、校验、审计 | OAuth2 / WAF |
| AI 风险 | Prompt 验证、输出过滤 | LangChain / Guardrails |
| 数据风险 | 备份、容灾 | 多活架构 |
| 技术风险 | 关键技术先行验证 | POC 原型 |
