# 开发路线

此文档是产品实现步骤与 Agent 执行指南，由 **TechLead** 负责维护。

## Agent 执行方案（Plan 中间层）

> 每次执行 step 前，先用 Plan 模式生成 `.cursor/plans/stepN-plan.md`，再由 Agent 执行。
> 详见 [.cursor/plans/README.md](./.cursor/plans/README.md)

### 工作流约定

| 顺序 | 步骤 | 说明 |
| ---- | ------------- | -------------------------------------------------------------------------- |
| 1 | **读取规格** | 读取 `doc/steps/stepN.md` 了解任务目标、要求、强约束 |
| 2 | **生成 Plan** | Plan 模式生成 `.cursor/plans/stepN-plan.md`（todos + 文件清单 + 验收标准） |
| 3 | **执行 Plan** | Agent 模式按 todos 顺序执行代码 |
| 4 | **验收闭环** | 对照 Plan 里的验收标准逐项确认 |

### 为什么用 Plan 作为中间层

- **规格与执行解耦**：`stepN.md` 是「做什么」，`stepN-plan.md` 是「怎么做、做成什么样」
- **减少执行跑偏**：todos 相当于执行路线图，AI 不会漏掉步骤或误解需求
- **可追溯**：每次执行都有 Plan 记录存档，回溯「当时为什么这么实现」比翻对话记录清晰

## 正确的开发顺序

### 阶段划分与依赖逻辑

| 阶段 | 包含步骤 | 核心依赖逻辑 |
| ------ | -------- | ------------------------------------------------ |
| 第零阶段：项目初始化 | step0 | 所有开发的前置条件，搭建 monorepo 结构、配置前端 Vue3 + 后端 NestJS + 共享类型 |
| 第一阶段：基础搭建 | step1、step6 | step1 前端项目初始化和 step6 后端 API 基础结构同步进行，形成完整项目框架 |
| 第二阶段：核心功能链路 | step2、step3、step4、step5 | 按依赖顺序开发：认证→权限→数据模型→版本控制→指标管理，每一步依赖前一步完成 |
| 第三阶段：功能深化 | step7、step8 | step6 完成后开发公式引擎，step7 完成后开发在线协作，形成完整的表格功能体系 |
| 第四阶段：DevOps 与集成 | step9a、step9b | step9a CI/CD 基础在 step5 后并行启动，step9b 集成测试需等 step9a 和 step8 都完成 |

### 为什么这样排序

- **第零阶段：项目初始化**：所有开发的前置条件，搭建 monorepo 结构、配置前端 Vue3 + 后端 NestJS + 共享类型
- **第一阶段：基础搭建**：step1 前端项目初始化和 step6 后端 API 基础结构同步进行，形成完整项目框架

### 各阶段详细步骤

#### 第零阶段：项目初始化

| step | 任务目标 | 说明 |
| ----- | ---------------------- | ----------------------------------------- |
| step0 | 初始化 monorepo 项目结构，配置前端 Vue3 + 后端 NestJS + 共享类型 | 搭建完整的 monorepo 结构，配置 pnpm workspaces，建立前后端基础项目模板，配置 TypeScript 类型共享机制 |

#### 第一阶段：基础搭建

| step | 任务目标 | 说明 |
| ----- | ---------------------- | ----------------------------------------- |
| step1 | 实现用户认证系统 | 用户注册、登录、Token 刷新、登出功能，使用 JWT 实现无状态认证 |
| step6 | 实现后端 API 基础结构 | NestJS 基础架构搭建，数据库连接配置，基础模块和服务层设计 |

#### 第二阶段：核心功能链路

| step | 任务目标 | 说明 |
| ----- | ---------------------- | ----------------------------------------- |
| step2 | 实现角色权限系统（RBAC） | 支持数据模型的访问控制，角色管理、权限分配、菜单权限控制 |
| step3 | 实现数据模型管理 CRUD | 数据模型创建、查询、更新、删除、列表功能，支持字段类型定义 |
| step4 | 实现数据模型版本控制系统 | 版本创建、发布、回滚、状态流转管理，支持版本对比和历史记录 |
| step5 | 实现指标管理功能 | 指标 CRUD、树形结构展示、分类管理，支持指标计算公式配置 |

#### 第三阶段：功能深化

| step | 任务目标 | 说明 |
| ----- | ---------------------- | ----------------------------------------- |
| step7 | 实现公式引擎 | HyperFormula 集成、常用财务函数实现，支持跨表引用和复杂计算 |
| step8 | 实现在线协作功能 | 协作者邀请、WebSocket 实时同步、冲突处理、协作历史追踪 |

#### 第四阶段：DevOps 与集成

| step | 任务目标 | 说明 |
| ----- | ---------------------- | ----------------------------------------- |
| step9a | 配置 CI/CD 基础流水线 | GitHub Actions 自动化构建、测试执行、代码质量检查 |
| step9b | 集成测试执行 + Docker 容器化 + 生产环境部署 | E2E 测试、Docker 镜像构建、K8s 部署配置、生产环境配置 |
