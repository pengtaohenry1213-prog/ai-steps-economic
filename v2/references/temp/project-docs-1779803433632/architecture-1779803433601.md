# T3项目架构设计文档

## 1. 架构概述

- 项目类型：T3
- 架构风格：分层架构 + 模块化 + 可插拔

## 2. 技术栈选型

### 2.1 前端技术栈

| 类别 | 技术选型 | 说明 |
|---|---|
| 框架 | Vue 3 | 渐进式框架，Composition API |
| 语言 | TypeScript | 类型安全 |
| 构建 | Vite | 快速开发体验 |
| UI组件 | vxe-table | 高性能表格组件 |
| 样式 | Tailwind CSS | 原子化CSS |
| 状态管理 | Pinia | Vue3官方推荐 |
| 路由 | Vue Router | 前端路由 |
| HTTP | Axios | HTTP客户端 |
| 公式引擎 | HyperFormula | Excel兼容公式引擎 |

### 2.2 后端技术栈

| 类别 | 技术选型 | 说明 |
|---|---|
| 数据库 | Supabase PostgreSQL | 开源Firebase替代 |
| 实时引擎 | Supabase Realtime | WebSocket实时同步 |
| 认证 | Supabase Auth | 开箱即用的认证 |
| 存储 | Supabase Storage | 文件存储 |
| Edge Functions | Deno/TypeScript | 服务端逻辑 |

### 2.3 数据存储

| 类型 | 技术选型 | 场景 |
|---|---|
| 关系型 | PostgreSQL | 业务数据存储 |
| 缓存 | Redis | 会话/公式缓存 |
| 向量 | pgvector | AI语义搜索（可选） |

### 2.4 AI 能力

| 类别 | 技术选型 | 场景 |
|---|---|
| AI模型 | MiniMax | 智能助手/自动填充 |
| 向量嵌入 | MiniMax Embedding | 文档语义检索 |

## 3. 系统分层架构

- 前端应用层（Vue3 + vxe-table）
- 接口网关层（Supabase REST API）
- 业务服务层（Supabase Edge Functions）
- 数据访问层（Supabase Client SDK）
- 基础设施层（Supabase/云服务）

## 4. 模块划分

### 4.1 前端模块

| 模块 | 说明 | AI增强 |
|---|---|
| packages/web - 主应用 | Vue3主应用，包含所有业务页面 | 否 |
| packages/ui - 组件库 | 自定义UI组件封装 | 否 |
| packages/utils - 工具函数 | 通用工具函数 | 否 |
| packages/types - 类型定义 | TypeScript类型定义 | 否 |
| packages/formula-engine | HyperFormula封装，v1财务函数集成 | 是 |

### 4.2 后端模块

| 模块 | 说明 | AI增强 |
|---|---|
| 数据库Schema | 基于v1的8张表设计，适配Supabase | 否 |
| Row Level Security | Supabase RLS行级安全策略 | 否 |
| Edge Functions | 复杂业务逻辑服务端函数 | 否 |
| Realtime Subscriptions | 在线协作实时订阅 | 否 |

## 5. 数据模型设计

### 5.1 核心实体
- 用户（users）
- 数据模型（datamodel）
- 模型版本（datamodelversion）
- 指标定义（modelmetric）
- 单元格数据（dataentry）
- 公式定义（modelformula）
- 页面配置（modelpage）
- 币种字典（currencydictionary）
- 单位分类（unitcategory）
- 角色（roles）
- 权限（permissions）
- 用户角色关联（user_roles）

### 5.2 关系设计
用户-角色(多对多)，角色-权限(多对多)，数据模型-版本(一对多)，版本-指标(一对多)，版本-单元格(一对多)，版本-公式(一对多)，版本-页面(一对多)

### 5.3 索引设计
- datamodel: idx_model_name, idx_model_status
- datamodelversion: idx_version_model, idx_version_status
- modelmetric: idx_metric_parent, idx_metric_code
- dataentry: idx_entry_version_row_col, idx_entry_formula
- modelformula: idx_formula_version, idx_formula_target

## 6. API 设计

### 6.1 接口规范
- RESTful API设计规范
- 统一请求/响应格式 {data, error, meta}
- JWT Bearer Token认证
- Pagination: cursor-based
- 版本控制: /api/v1/*

| 类别 | 接口 | 说明 |

## 7. 部署架构

### 7.1 环境规划

| 环境 | 用途 | 流量 |
|---|---|
| dev | 开发调试 | 内部 |
| test | 集成测试 | 内部 |
| staging | 预发布 | 少量外部 |
| prod | 生产环境 | 100% |

### 7.2 部署方式

| 组件 | 部署方案 | 说明 |
|---|---|
| 前端Web应用 | Vercel/CDN | 静态托管，自动部署 |
| Supabase服务 | Supabase托管 | Managed服务，自维护PostgreSQL |
| Edge Functions | Supabase Edge | 边缘计算，随Supabase部署 |
| Redis缓存 | 云Redis服务 | 如Supabase不提供独立缓存 |
