# T2项目架构设计文档

## 1. 架构概述

- 项目类型：T2
- 架构风格：分层架构 + 模块化 + 可插拔

## 2. 技术栈选型

### 2.1 前端技术栈

| 类别 | 技术选型 | 说明 |
|---|---|
| 框架 | Vue 3 | 渐进式框架，Composition API |
| 语言 | TypeScript | 类型安全，提升代码质量 |
| 构建 | Vite | 快速HMR，开发体验优秀 |
| UI框架 | Tailwind CSS | 原子化CSS，快速定制 |
| 表格组件 | vxe-table | 高性能表格组件 |
| 状态管理 | Pinia | Vue 3官方推荐状态管理 |
| Monorepo | Turborepo | 统一管理多子项目 |

### 2.2 后端技术栈

| 类别 | 技术选型 | 说明 |
|---|---|
| 运行环境 | Node.js 18+ | 非阻塞IO，高并发 |
| 框架 | Express/Koa | 轻量级Web框架 |
| ORM | Prisma | 类型安全的数据访问 |
| 实时通信 | Supabase Realtime | WebSocket实时能力 |

### 2.3 数据存储

| 类型 | 技术选型 | 场景 |
|---|---|
| 关系型 | PostgreSQL | 业务数据存储（直接复用v1设计） |
| 时序数据库 | TimescaleDB | 时序数据（日志、监控） |
| 缓存 | Redis | 会话缓存、公式计算缓存 |
| 向量 | pgvector | AI语义搜索 |

### 2.4 AI 能力

| 类别 | 技术选型 | 场景 |
|---|---|
| 模型 | MiniMax | 智能公式建议、异常检测、自然语言查询 |
| 监控 | LangSmith | AI能力调用追踪 |

## 3. 系统分层架构

- 前端应用层（Vue 3 + Tailwind CSS）
- 接口网关层（Nginx/API Gateway）
- 业务服务层（Express/Koa + 业务逻辑）
- 数据访问层（Prisma + PostgreSQL）
- 基础设施层（Supabase/Redis/监控）

## 6. API 设计

### 6.1 接口规范
- RESTful API设计规范
- 统一请求/响应格式（{code, message, data}）
- JWT Token认证
- 分页规范（cursor/page两种模式）
- 错误码规范（分类编码）

### 6.2 核心接口清单

| 类别 | 接口 | 说明 |
|---|---|
| 认证授权 | POST /api/auth/register | 用户注册 |
| 认证授权 | POST /api/auth/login | 用户登录 |
| 认证授权 | POST /api/auth/refresh | Token刷新 |
| 认证授权 | POST /api/auth/logout | 用户登出 |
| 模型管理 | GET /api/models | 模型列表查询 |
| 模型管理 | POST /api/models | 创建模型 |
| 模型管理 | GET /api/models/:id | 获取模型详情 |
| 模型管理 | PUT /api/models/:id | 更新模型 |
| 模型管理 | DELETE /api/models/:id | 删除模型 |
| 版本控制 | GET /api/models/:id/versions | 版本历史 |
| 版本控制 | POST /api/models/:id/versions | 创建版本快照 |
| 版本控制 | POST /api/models/:id/versions/:vid/switch | 切换版本 |
| 版本控制 | GET /api/models/:id/versions/compare | 版本对比 |
| 公式计算 | POST /api/models/:id/formulas | 定义公式 |

| 公式计算 | GET /api/models/:id/dependencies | 依赖分析 |
| 数据操作 | GET /api/versions/:vid/data | 获取版本数据 |
| 数据操作 | PUT /api/versions/:vid/data | 更新单元格数据 |
| 导入导出 | POST /api/import/upload | 上传导入文件 |
| 导入导出 | POST /api/import/confirm | 确认导入 |
| 导入导出 | GET /api/export/:modelId | 导出模型 |
| AI能力 | POST /api/ai/suggest | 智能公式建议 |

## 7. 部署架构

### 7.1 环境规划

| 环境 | 用途 | 流量 |
|---|---|
| dev | 开发调试 | 内部开发团队 |
| test | 集成测试 | 测试团队 |
| staging | 预发布验证 | 少量外部用户 |
| prod | 生产环境 | 100%正式用户 |

### 7.2 部署方式

| 组件 | 部署方案 | 说明 |
|---|---|
| 前端应用 | Vercel/CDN | 静态托管，全球加速 |
| 后端服务 | Docker容器化 | Docker Compose或K8s部署 |
| 数据库 | 云数据库托管 | PostgreSQL云服务，自动备份 |
| 缓存 | 云缓存服务 | Redis云服务，集群部署 |
| Supabase | 云服务 | 实时能力，BaaS服务 |
