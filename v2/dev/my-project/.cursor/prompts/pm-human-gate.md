# Human Gate：PM 需求评审

## 触发时机

- Plan/PRD 提交评审时
- 需求变更范围≥20%时
- 里程碑节点验收时

## Gate 检查项

### 1. 需求完整性

- [ ] 背景与目标清晰（可量化更好）
- [ ] **不做清单**明确（Out of Scope）
- [ ] 用户与场景定义完整

### 2. 验收标准

- [ ] 功能验收标准可执行、可观测
- [ ] 非功能需求明确（性能/安全/兼容）
- [ ] 异常与边界场景覆盖

### 3. 优先级

- [ ] P0 缺失则核心价值不成立
- [ ] P1 主路径清晰
- [ ] P2/P3 有则说明

### 4. 依赖与风险

- [ ] 外部依赖（数据/接口/法务）已识别
- [ ] 开放问题有责任人
- [ ] 风险有应对方案

## 统一决策格式

所有 Human Gate 必须使用以下统一决策格式：

| 决策 | 条件 |
|------|------|
| **PASS** | 所有检查项通过，可继续执行 |
| **CONDITIONAL** | 非核心项未达标，但不影响主路径，需记录整改项 |
| **REJECT** | 核心项缺失或不明确，必须修复后才能继续 |

## 决策记录

```markdown
## Human Gate 决策

| 项目 | 内容 |
|------|------|
| Gate 类型 | PM / PMO / Security |
| 提交时间 | YYYY-MM-DD HH:mm |
| 决策 | PASS / CONDITIONAL / REJECT |
| 决策依据 | ... |
| 整改要求（如有） | ... |
| 整改期限（如有） | ... |
| 签字 | ___ |
```

## 闭环要求

- 决策需在提交后 **24h 内**给出
- CONDITIONAL/REJECT 需跟踪至整改完成并重新决策
